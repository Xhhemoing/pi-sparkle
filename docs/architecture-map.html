从入口到源码集成，32 个关键节点沿现有调用与事实边界展开。四个核心是同一模块化单体的责任分区；右侧增强按需接入，不成为普通任务的必经流程。

对话如何连接这些能力：自然语言入口 · 小任务与项目长线衔接（接线方案）。

01 / entry 已有源码能力

CLI 与开发命令

main / develop

输入
用户目标、项目路径、宿主配置与明确授权。
输出
调用现有 run 或严格 develop；不是所有命令都先进入同一 controller。
决定权
入口解析与装配输入；不能以命令执行成功替代任务验收。
协作
严格 develop 进入 DevelopmentController；其他运行入口可直接使用现有 run 路径。
限制与状态
不同命令能力不同。此图突出严格开发主链，不宣称所有入口已统一。

一次严格开发任务 控制请求与返回证据分开看

为什么不把 run 成功当作完成？

run 描述内部执行是否结束；工作项接受需要当前候选通过宿主验收；源码集成需要独立应用。三者是不同粒度，不能压成一个 SUCCESS。

普通任务如何更轻？

设计中的直接入口复用写会话，省去不必要的队列和规划。它不会静默降低现有 strict develop 的保护路径、检查与明确应用边界。

取消、对账与恢复 实际停止是写入移交的前提

已发生的效果保留；迟到结果可标过期，但效果收据与用量不能一并丢弃。源码或定义变化后，旧检查证据不自动适用。

Pi 更新与运行绑定 新任务采用合格组合，旧运行继续可解释

产品不永久锁死某一内核版本；每次运行仍绑定精确已知组合。破坏性语义变化要适配和验证，不承诺任意未来版本零改动。

插件究竟接在哪里 窄贡献，宿主保留编排与验收

目标入口为 sdk / host / testing，尚未公开为稳定生产 API。fixture 验证贡献行为，不授予业务验收或应用权限。
