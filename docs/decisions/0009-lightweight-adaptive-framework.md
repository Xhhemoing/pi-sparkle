# ADR-009: Pi-sparkle 当前架构——轻量核心与按需适应

- 日期：2026-10-16。
- 状态：**Accepted（设计方向）**。用户明确接受经审阅的架构，要求写入项目并形成持续维护的宣讲入口。
- 范围：职责边界、默认体验、算法选择与迁移原则；本次交付仅修改文档。
- 实施入口：[当前架构](../framework.md)、[算法契约](../architecture-algorithms.md)、[迁移计划](../architecture-migration.md)。
- 本轮任务：[current-architecture-guide](../superpowers/plans/2026-10-16-current-architecture-guide.md)。

## 背景

项目已有运行日志、调度、候选工作区、宿主检查、项目队列和受控策略提案。若所有能力都进入默认路径，普通开发就会先承担规划、预算、实验和插件平台的配置成本；若为简化而去掉效果证据与停止责任，又会破坏已有恢复和验收边界。

用户要求边分析边推进，及时修复重要问题；简单任务保持松散，金额预算不逐项强制；框架持续跟进 Pi，并根据可纠正的偏好与当前需求改进交付。本决策选择小核心、按影响升级流程、独立事实所有权和可退出的可选能力。

## 决策

### 1. 四个职责，复用模块化单体

按任务与授权、执行与资源、工作区与检查、状态与恢复组织代码与责任。它们不是四个新服务、包、调度器或模型阶段。复用 DevelopmentController、既有 run 路径、Pi adapter、WorkQueue、ActionLedger、事件与 Git，不新建竞争性的任务完成状态或 ProjectState 数据库。

先解除明确的服务到 CLI 倒置、分开底层状态布局与应用维护，再验证窄 SDK。物理拆包需有真实独立消费者或交付需求，不按现有目录数拆包。

### 2. 默认单 worker，按事实升级流程

普通任务无需队列、独立 planner、金额表单、全仓索引或评审委员会。按授权、可逆性、公共契约影响、外部效果和证据选择调查与检查，不以字数或文件数代替风险。已有授权持续生效，必要决定缺失时才询问。

现有严格 `develop` 的宿主检查、保护路径、候选绑定、显式验收和应用条件保持原语义。轻量入口省去不需要的编排，不在原命令下静默降低验收。

### 3. 动态观察，明确写入责任

默认观察已有事件，按同因与证据版本去重；必要时才启动短时只读分析。即时危害先请求停止受影响动作，实际结束或对账后再交接写入。每个候选范围保持单写入责任，scout 不取得写入权；旧快照结果不能作用于新候选。

当前用户指令、任务事实、表现偏好与后续计划可在合适边界更新。运行代码、已批准学习策略、在飞操作的授权和验收事实保持稳定绑定。新授权由宿主显式记录；诊断不能升级为用户指令。定义/源基线改变后重验，旧证据不转移。

### 4. 费用可观察，严格准入可选

默认观察费用，支持会话/项目继承和提醒；unknown 不计为零。明确的强制上限不能被下层设置撤销。严格准入需要可靠的下一调用上界、原子预留、结算和未知效果对账；缺可靠上界就拒绝新调用，不静默降级。

严格准入是本系统的准入约束，不是供应商最终账单保证。不同累计范围需要各自账本，取上限最小值不能替代范围结算。无金额上限仍保留取消、操作边界和有限修复。

### 5. 通过资格验证持续更新 Pi

保留精确已知版本作为当前基线和回退。目标先在 standalone 路径增加受管独立进程 driver：候选安装、行为验证、不可变 generation、批准指针、新 root run 绑定；子任务/重试继承，恢复使用原绑定。失败候选不覆盖已知可用版本；已有或未知外部效果不能跨版本盲重放。

原生 Pi 宿主是独立兼容和生命周期边界，更新需要新宿主进程；首期不跨 IPC 搬函数认证或复制完整 AgentSession。用户可预先选择稳定自动渠道；未知破坏性变化先适配再认证。当前 package pin、peer 范围与已加载引擎未因本 ADR 改变。

### 6. 显式偏好直接生效，学习保持证据边界

使用 user/project/task 分层的少量偏好，记录来源、scope、时效、替代关系和删除标记。当前明确要求优先，task overlay 不污染长期默认。明确长期设置、纠正和删除不经过实验、holdout 或晋升；tombstone 防旧来源复活。

推断低于明确要求，不能获得授权。算法改进先归因、离线比较与 shadow，再按既有批准/CAS 流程试用。未来有限自动化需要明确预授权范围和实际验证的停止/回滚链；满意度不能替代正确性、验收或失败披露。

### 7. 扩展少量、按需、可关闭

首批拟稳定公开的贡献仅 context fragment 和 diagnostic adapter；tool/observer 留待实际需求驱动的实验。采用静态声明、显式启用、lazy activation、唯一 ID、暂存注册和 generation 拒绝过期提案；迟到效果收据与用量仍记录并幂等结算。插件不取得 accept/apply、raw store、凭据或 Pi 宿主对象。同进程插件是可信代码，接口与 `node:vm` 不提供不可信代码沙箱。

项目推进是现有队列上的薄函数，认领仍由 controller/store 完成。动态计划只扩展现有 store，先处理未开始项，不建第二套计划状态。外部连接先只读草稿、再写自身进展区；传输去重独立、有界，业务外部效果复用 ActionLedger。不承诺默认后台项目经理或内置 cron。

## 未选择的方案

- 每任务完整规划、评审与实验：无关成本过高，改为按需启用。
- 默认多 agent、在线 bandit、自修改内核：效果与恢复证据不足，单 worker 与规则起步。
- 微服务、按目录拆大量包、万能 hook 平台：增加部署、兼容和协调负担。
- 原地 import 最新 Pi 或在飞热换：无法保证模块、资源所有权及效果重放语义。
- 全双向外部状态覆盖、独立 ProjectState：制造冲突权威与跨系统事务。
- 人格摘要推断授权、满意度替代验收：缺乏可解释事实，易污染当前目标。

## 后果与实施验收

持续检查可选能力是否进入默认加载、普通任务是否增加纯流程模型调用、插件是否深依赖内部实现，以及是否新增第二套成功状态。轻任务强制金额字段、强制队列文件、未触发插件执行的目标为零；不据此预报启动或费用改善比例。

按 [M0–M7](../architecture-migration.md)独立推进：先可靠停止和直接任务可用，再做可选增强，不要求所有优化共同阻塞核心交付。本轮只将设计落库，运行时、接口、依赖和持久数据没有变化；实施与效果验收使用之后各切片的真实证据。
