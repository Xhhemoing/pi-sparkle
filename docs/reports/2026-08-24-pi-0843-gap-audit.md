`cursor/pi-adapt-aux-features-e1e3`. Method: every claim below comes from this

## 3. Gaps found

### G1 (P0, merge-blocking): boundary tripwire false-positives on pi-compat — RESOLVED, see §6

`test/unit/pi-boundary.test.ts` fails on this branch:

```
+ actual: ['/workspace/src/cli/pi-compat.ts', '/workspace/src/pi-compat/check.ts']
- expected: []
```

The test flags any source file whose *content contains* the string
`@earendil-works/` (`content.includes(...)`, line 29). The two new pi-compat
modules mention the package **names as data** (pin lookup keys, registry
URLs, finding messages) and import nothing from Pi — ADR-001 is honored in
spirit but the tripwire tests string presence, not import statements. As
written, `pnpm gate` fails and the PR cannot merge.

Fix (Round 2, one line of intent): match import/require *specifiers* (for
example `from "@earendil-works/…"` / `import("@earendil-works/…")`) instead
of raw substring presence. Do not weaken it to a path allowlist — pi-compat
must stay unable to import Pi types, only to name them.

### G2 (P1): pi-compat report body scans prose docs for the legacy identifier — RESOLVED, see §6

`src/pi-compat/check.ts` `readDefaultAdapterSource()` concatenates
`docs/how-to-adapt-to-pi.md` and `SKILL.md` with the adapter sources, then
`inspectAdapterSource()` greps the *combined* text for the legacy Google
thinking-level identifier. The exit-code path is already protected
(`src/cli/pi-compat.ts` re-probes with `readAdapterSourcesOnly()`), but the
**printed/JSON report** is not: a documentation file that merely names the
pre-rename identifier verbatim flips the human-facing report to
`google-thinking=legacy-…` plus a `BROKEN:` finding while exiting 0 — a
confusing false alarm. The how-to doc currently works around this by never
spelling the identifier contiguously (see its Maintainer notes).

Fix: in `check.ts`, run the legacy-identifier probe over adapter sources
only; keep the docs/SKILL.md concatenation solely for the
nested-skill-discovery evidence regex. Related fragility: only `SKILL.md` is
scanned from the skill tree — `references/pi-version-adapt.md` *does* spell
the legacy identifier today and is safe only because it is not on the
evidence list; anyone extending that list would trip G2.

### G3 (P1): thinking-level triple mirror has no drift test — still open, see §6

The level list exists in three places (agent-core `ThinkingLevel`,
`THINKING_LEVELS` in `src/cli/main.ts`, `SPARKLE_THINKING_LEVELS` in
`src/pi-compat/check.ts`). Nothing fails if Pi adds an eighth level: the CLI
would silently reject it as an invalid `PI_THINKING_LEVEL` value. A unit test
in `test/unit/pi-adapter/` (inside the boundary, so it may import the Pi
type) can assert the mirrors equal the imported union via a
`satisfies`-style exhaustiveness check.

### G4 (informational): `translatePiEvent` drops unknown event types silently

By design (`default: return undefined`), which is the right forward-compat
posture — but it means an additive `AgentEvent` variant carrying data we
*want* (as `turn_end` usage once was) arrives as silence, not as a failure.
The playbook's step 1 ("read the diff, not just typecheck") is the standing
mitigation; no code change recommended now.

### P1 — next round

1. `--thinking <level>` CLI flag on `run` (and `--track`), defaulting to
   `PI_THINKING_LEVEL`, validated against the same list. This is the headless
   counterpart of Pi's session-scoped `/thinking` TUI selector; per-run
   scoping matches Pi's session scoping. Small: `src/cli/main.ts` arg parsing
   plus the existing `createConfiguredPiExecutor` `thinkingLevel` input.
2. `toolChoice` passthrough **only if** an executor use case appears (for
   example forcing `"none"` for a pure-analysis child task). Plumbing:
   optional field on `PiExecutorOptions`, spread into the `streamSimple`
   options where `apiKey` already is. Zero urgency: the adapter already
   passes through whatever Pi's `Agent` sets.
3. Nested-skill doctor check: validate the shipped `.agents/skills` tree
   against the 0.84.3 discovery rules (every leaf skill dir has `SKILL.md`
   with `name`/`description` frontmatter; grouping dirs contain skill dirs;
   README/AGENTS.md presence is *not* an error). Catches packaging drift
   before `pi install` does.
4. G2 + G3 fixes above.

### P2 — later, gated on policy

1. `session_compact_failed` (and any extension-event) handling: **only if
   ADR-006 is ever Accepted** and an `extensions/pi-sparkle/` reverse adapter
   exists. Until then this is explicitly a non-feature; do not pre-build for
   it.
2. `thinkingBudgets` / `thinking.budget` passthrough for token-budget
   providers — only when a custom provider config actually needs it.
3. Scheduled online compat check (CI cron running
   `pi-compat --online` / `pi-latest-check.mjs`) — needs network policy
   decision first; both tools already fail closed.

## 5. Bottom line

0.84.1 → 0.84.3 is a **no-code-change bump for the adapter**: the one
breaking rename touched a symbol this repo never imported, agent-core's
consumed surface is byte-identical, and everything else is additive and
flows through the existing options spread. The P0 auxiliary surface
(pin + pi-compat + doctor + probes) landed in Round 1 and verifies green;
the single merge blocker is the over-broad boundary tripwire (G1), a test
refinement, not an adapter change.
