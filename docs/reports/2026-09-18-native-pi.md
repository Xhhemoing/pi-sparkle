## Behavioral Evidence

- `extensions/pi-sparkle/index.ts` registers a lazily loaded native tool. The existing `/sparkle` prompt remains reachable; status uses `/sparkle-status`. Factory startup does not start background work or load the orchestration graph. `SPARKLE_NATIVE=0` registers nothing.
- `src/native/session.ts` resolves a unique preferred model, rejects unavailable/ambiguous choices, accepts 1–4 nonempty scout/reviewer tasks, uses the existing `startParentRun` / child-tracking path, persists events, returns bounded reports and run ID, and invokes proposal-only analysis after completed/failed execution. Input abort/shutdown cancels child signals and waits for the coordinator. Pre-abort creates no state.
- `src/pi-adapter/native-executor.ts` exposes only the existing bounded file-read tool plus task reporting. It uses the host's effective provider and request-time authentication callback; it does not construct another credentials store or write authentication/configuration. No worker shell, writes or recursive spawn tools are provided.
- HTTP/SSE loopback drives an actual read through the native adapter. The test also invokes the tool obtained from the real Pi loader through the shared coordinator and asserts the returned run identity and UNOBSERVED independent acceptance. Scripted provider output is synthetic, not evidence of model quality.
- No ambient Pi conversation listener or hidden thinking capture was introduced. Post-run analysis is bound to the delegated run's events and a run-local signal directory, rather than importing another extension's `.pi/subagents/runs` history.
- Native sources are included in package files because Pi loads the TypeScript entry directly; the CLI build layout remains unchanged. Existing outbound import whitelist remains, with an explicit inbound-directory guard.
