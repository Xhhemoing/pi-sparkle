**诚实空枚举：无达门槛的新更优解，未铸任何 S21-D-\* ID，切片零代码
改动；整片预算收口第二十一次复核成立，并关掉一条二十遍从未定价的
完备性轴——「状态增长方向面」（lifecycle 深度 × 广度 × 纯结构
二次项）：R8-D…R20-D 把注册表状态维度要么按**比例剂量**定价
（R14-D 的规模越线标定把 promptCount 乘 k×8——每个身份 ≤2 个版本，
纯**广度**扫掠）、要么按**单载荷字节**定价（R16-D 的 P 轴在固定
基数下放大策略字节）、要么在**固定生产形态**上定价命令相位
（R13-D 21 相位 / R18-D 锁事务账目）——但生产状态增长实际采取的
**方向**从未被隔离：每次对**同一个**资源 `adapt promote` 恰好向
**一条**身份链追加 1 版本 + 1 已批候选 + 2 台账项（intent+promoted）
+ 1 内容 blob（lifecycle **深度**；生产中唯一会老化的身份正是
`learning/learned-routing.ts` L39 的单个 routing-policy 身份），而
切片内唯一单命令成本随状态**超线性**增长的结构位恰好只存在于深度
方向——`ResourceRegistry.addVersion` 用拷贝追加重建每身份版本表
（`[...existing, version]`，S1-D-1 属性：可变 push 被排除因为调用方
经 `versionsFor()` 持有该数组），restore 一条深度 n 的链付
Σ(1..n) = O(n²) 元素拷贝，而 restore n 条深度 1 的行只付 O(n)
（批量重建消除 = S2-D-1，当年按「V 个位数、~250ns」排除——本轴
给出的正是 S2-D-1 重开阈值的完整曲线）。本轮以真实 promote 驱动的
确定性夹具把该面四段关死（附录脚本三次独立运行全绿）：**

1. **深度老化全命令面（S1a）**：单个 prompt 身份经 N ∈ {8, 32,
   128, 512, 2048} 次**真实** promote（createCandidate +
   promoteWithRegistry 全门链）老化，每层定价全命令面：文件从
   24.7 KB 长到 6.14 MB，load 0.20→40.5–43.9 ms、save(+fsync)
   0.63→28.2–33.9 ms、status 体 0.19→38.1–39.3 ms——全部随字节
   线性；而全部 op-only 腿留在 µs 级：每 promote 操作
   14.7→31.3–59.9 µs、rollback（双向 CAS）17.0→104.5–176.8 µs、
   `ledger()` 拷贝 0.1→1.4–3.1 µs（L=4096）、`candidatesFor` 扫描
   1.2→20.5–31.5 µs（C=2048）、createCandidate（无环谱系全链走查）
   15.0→162.2–241.7 µs。链完整性见证逐层通过（active==tip、
   versionsFor==N+1、台账==2N、父链抽查、rollback 双向 CAS）。
2. **方向不敏感判决（S1b 广度对照，等操作者活动）**：同样 N 次
   promote 摊到 N 个不同身份（每身份深度 2）——广度臂在等活动下
   携带**更多**状态（V=2n、B=2n；n=2048 时 7.39 vs 6.14 MB），
   load 10 ms 越线反而**更早**（n≈480–490 vs 深度臂 498–532）。
   每字节 load 单价两臂同为 ~6–7 ns/byte（≈140–170 MB/s
   解析+校验），**e2e 命令成本由字节支配、对增长方向不敏感**；
   深度独有的结构二次项在全部可行寿命内是次要项（n=2048 时占
   e2e load 的 ~5%，见 S1c 交叉核对）。
3. **纯结构二次项隔离 + S2-D-1 重开阈值量化（S1c）**：仅含版本的
   合成快照（无 blob/台账/候选/I/O）深度链 vs 广度行对照，
   V ∈ {512, 2048, 8192}：残差（深度−广度）0.13–0.20 / 1.86–2.22 /
   33.35–34.83 ms，8192/2048 残差比 15.7–18.7（纯 N² 期望 16），

## 2. 新轴：状态增长方向面（lifecycle 深度 × 广度 × 纯结构二次项）

方法：二十遍的状态定价全部是**标量剂量**——R14-D 把整个配置态
夹具乘 k（身份数 ×k，每身份 ≤2 深：广度）、R16-D 把单版本字节乘
剂量（基数不变：载荷）、R13-D/R18-D 固定生产形态定价相位/事务、
R20-D 固定形态定价进程共存——没有一遍把「同样多的操作者活动落在
**一条链**还是**一片行**上」作为自变量。而这恰是唯一有结构意义的
方向选择：切片内单命令成本对状态的依赖里，唯一超线性项
（`addVersion` 拷贝追加 → restore 深链 O(n²)）只在深度方向存在；
台账拷贝（S3-D-1）、候选扫描（S1-D-2）、无环走查、rollback 校验
扫描全部是深度方向的 O(n) 项、广度方向的 O(1)/O(n) 项。本轮四段
仪器：(2a) 深度老化驱动（一条身份 N 次真实 promote，逐层全命令
面）；(2b) 等活动广度对照（N 身份 × 1 promote）；(2c) 纯结构隔离
（仅版本合成快照，深度链 vs 广度行，二次项系数与 10 ms 越线）；
(2d) 全腿最小二乘越线求解。判读标尺沿用历轮验收线（数十–数百 ms
稳态；once-per-command µs 与幻想规模越线是拒绝类）。附带 (2e)
round-trip 见证中新钉的序列化定点事实。

### 2f. 天花板裁决（频率 × 单价 × 属地三端封死）

- **频率端**：深度增长 = 对同一资源的批准 promote 次数。生产结构：
  唯一老化身份（learned-routing 策略）proposal-first + 显式批准门 +
  auto-loop 每 run 至多一次提议——深度速率为个位数/轮量级；生产
  锚深度 2–3。最早 e2e 越线 ~500、纯二次项越线 ~4.4k：分别差两个
  和三个数量级。广度端已由 R14-D 标定（本轮广度臂仅作对照，不重
  标）。
- **单价端**：op 腿在 N=2048 幻想态全体 µs 级（20–242 µs）；e2e
  腿的 ms 都是字节价（~6–7 ns/byte，两方向同价），且在生产锚只有
  0.7–0.9 ms（load）；纯二次项在生产深度 ~5 ns。全部低于落地线
  （数十–数百 ms 稳态）一到十个数量级。
- **属地端**：每条消除路径撞死：可变 push = S1-D-1 重铸（调用方持
  `versionsFor()` 数组，别名破坏）；restore 批量重建 = S2-D-1 重铸
  （本轴量化其重开阈值 ~4.4k 深度，未触发）；candidatesFor 身份
  索引 = S1-D-2 重铸；ledger() 拷贝消除/惰性视图 = S3-D-1 重铸 +
  别名泄漏；无环走查缓存/弱化 = fail-closed 环守卫 fail-open 化
  （明文冻结）；版本剪枝/链紧缩/台账分段/快照分文件 = 数据面与
  审计契约变更（rollback 目标必须全量在册、台账是审计链、
  retiredVersionIds 语义）——架构级不可提案域；字节正则序列化 =
  零收益搅动（2e）。**三端封死，无新缝隙。**

function mulberry32(seed: number): () => number {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) >>> 0;
    let t = a;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

/** Recursively sort object keys so JSON compare ignores key order. */
function canonicalJson(value: unknown): string {
  return JSON.stringify(value, (_key, val: unknown) => {
    if (val !== null && typeof val === "object" && !Array.isArray(val)) {
      const sorted: Record<string, unknown> = {};
      for (const k of Object.keys(val as Record<string, unknown>).sort()) {
        sorted[k] = (val as Record<string, unknown>)[k];
      }
      return sorted;
    }
    return val;
  });
}

/** Ordinary least squares for t = a + b*x (returns [a, b]). */
function fitLinear(xs: readonly number[], ts: readonly number[]): [number, number] {
  const n = xs.length;
  let sx = 0;
  let st = 0;
  let sxx = 0;
  let sxt = 0;
  for (let i = 0; i < n; i += 1) {
    sx += xs[i] as number;
    st += ts[i] as number;
    sxx += (xs[i] as number) * (xs[i] as number);
    sxt += (xs[i] as number) * (ts[i] as number);
  }
  const b = (n * sxt - sx * st) / (n * sxx - sx * sx);
  const a = (st - b * sx) / n;
  return [a, b];
}

/** Age ONE prompt identity through n real promotes; return the registry + chain. */
function buildDepthLifecycle(tag: string, n: number): {
  registry: ResourceRegistry;
  identity: ResourceIdentity;
  chain: ResourceVersion[];
  lastPromoteUs: number;
} {
  const registry = new ResourceRegistry({ now: () => NOW, generateId: sequentialIds(tag) });
  const identity: ResourceIdentity = {
    kind: "prompt",
    name: "agent-prompt-aged",
    scope: { kind: "project", projectId: createProjectId(() => `${tag}proj`) }
  };
  const contentAt = (step: number): string =>
    `# prompt r21d-depth step ${step}\n${PROMPT_FILLER}`;
  const chain: ResourceVersion[] = [registry.registerBaseline({ identity, content: contentAt(0), author: HUMAN })];
  const tail = Math.min(8, n);
  let tailTotalMs = 0;
  for (let i = 1; i <= n; i += 1) {
    const parent = chain[chain.length - 1] as ResourceVersion;
    const content = contentAt(i);
    const t0 = performance.now();
    const candidate = registry.createCandidate({
      identity,
      content,
      parentVersionId: parent.versionId,
      author: HUMAN,
      evaluationPlan: EVAL_PLAN
    });
    const result = promoteWithRegistry(registry, {
      candidateId: candidate.candidateId,
      expectedCurrentVersionId: parent.versionId,
      content,
      approvedBy: HUMAN,
      review: mkReview(candidate.candidateId, candidate.contentHash, `${tag}s${i}`),
      changeNote: mkNote(`prompt:${tag}${i}`, parent.versionId),
      explicitApproval: true
    });
    const dt = performance.now() - t0;
    if (i > n - tail) tailTotalMs += dt;
    chain.push(result.newVersion as ResourceVersion);
  }
  return { registry, identity, chain, lastPromoteUs: (tailTotalMs / tail) * 1e3 };
}

/** The same n promotes spread over n distinct identities (depth 2 each). */
function buildBreadthLifecycle(tag: string, n: number): {
  registry: ResourceRegistry;
  identities: ResourceIdentity[];
  tips: ResourceVersion[];
  lastPromoteUs: number;
} {
  const registry = new ResourceRegistry({ now: () => NOW, generateId: sequentialIds(tag) });
  const identities: ResourceIdentity[] = [];
  const tips: ResourceVersion[] = [];
  const tail = Math.min(8, n);
  let tailTotalMs = 0;
  for (let i = 0; i < n; i += 1) {
    const identity: ResourceIdentity = {
      kind: "prompt",
      name: `agent-prompt-${i}`,
      scope: { kind: "project", projectId: createProjectId(() => `${tag}proj`) }
    };
    const base = `# prompt r21d-breadth id ${i}\n${PROMPT_FILLER}`;
    const amended = `${base}## amendment ${i}\n`;
    const v1 = registry.registerBaseline({ identity, content: base, author: HUMAN });
    const t0 = performance.now();
    const candidate = registry.createCandidate({
      identity,
      content: amended,
      parentVersionId: v1.versionId,
      author: HUMAN,
      evaluationPlan: EVAL_PLAN
    });
    const result = promoteWithRegistry(registry, {
      candidateId: candidate.candidateId,
      expectedCurrentVersionId: v1.versionId,
      content: amended,
      approvedBy: HUMAN,
      review: mkReview(candidate.candidateId, candidate.contentHash, `${tag}b${i}`),
      changeNote: mkNote(`prompt:${tag}${i}`, v1.versionId),
      explicitApproval: true
    });
    const dt = performance.now() - t0;
    if (i >= n - tail) tailTotalMs += dt;
    identities.push(identity);
    tips.push(result.newVersion as ResourceVersion);
  }
  return { registry, identities, tips, lastPromoteUs: (tailTotalMs / tail) * 1e3 };
}
