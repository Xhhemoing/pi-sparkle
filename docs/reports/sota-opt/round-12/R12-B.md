## 1. 第十二遍搜索方法：结构位置 × 消除机制全叉积 + prior 盲区透镜

R1-B「输出契约渐近下界」…R10-B「矩阵补格/条件死计算下沉/常量域死卫/微阵列
反索引」、R11-B「跨阶段融合 + 输入侧形状探针」。本轮第十二组把切片摊成
12 个结构位置（批设置 / 任务分析 / 策略装配 / 路由校验 / 默认解析 /
过滤主循环 / 选择 / 决策构造 / 拒绝路径 / 级联 / 库 R0 / 目录构造）×
19 类消除机制（死代码、去重、提升、索引、反索引、融合、裂解、惰性、预计
算、记忆化、享元、早退、短路重排、单态化、表示变换、代数恒等、别名/免
拷贝、批处理、并行）做全叉积，对照排除表逐格清点。全叉积后仅两格未被
任何闭合 ID 覆盖：

1. **过滤主循环 × 反索引**（产出 S12-B-1）：`partitionLiveCandidates` 的
   per-route `new Set(input.modelPolicy.allowedModels)` 是切片内最后一个
   每 route 分配的索引结构。R2-B 曾把该站点记为「现状合理（S1-A-4 教训
   域）」但从未测过反方向；R10-B 用同一透镜测的是 validateConfig
   （S10-B-3，每批一次站点）。与 S6-B-5（跳过 Set——长度守卫不健全）、
   S3-B-1（记忆化整个 partition——更慢）、S1-A-4/S1-B-6（相反方向
   array→Set）站点或方向均不同，非换名。
2. **策略装配 × 记忆化**（产出 S12-B-2）：`assignPlanned` 每任务调用
   `pickPreferredModel(plan, analysis, prior)`，其 prior 层调用

## 2c. 新测量格：prior≠undefined（矩阵最后盲区闭合）

**流量取证**（§1 第 3 条）：传 prior 的生产调用方仅 CLI live face
（N≤30）与 track loop/primary-split（C≤~6）；唯一 N=2000 级调用方
eval-routing **不传 prior**。故分两档测量：

```text
matrix prior HYPOTHETICAL replay N=2000 [M=2 default, prior]: 37.77–38.46ms per eval x2
matrix prior HYPOTHETICAL replay N=2000 [M=7 configured, prior]: 53.02–54.06ms per eval x2
matrix prior HYPOTHETICAL replay N=2000 [M=10 stress, prior]: 79.43–79.98ms per eval x2
matrix prior REAL-SCALE live face N=30: M=2+prior 210.7–215.3us | M=7+prior+learned 323.7–330.4us per call
prior unit cost: pickFromPublicPrior(edit, M=7 pool, 56-row snapshot) = 19706–19810ns per call
```

三条结论：

1. **假设规模下 prior 是首个越线配置**：M=7+prior 53.0–54.1 ms/eval，
   为全战役 B 切片首次测出「若有流量则超过落地线」的邻接配置——每次
   pick 19.7 µs × ~55–65% 非 preferPrimary 任务 × N=2000 × 2 调用。
   成本主体在 `pickFromPublicPrior`（切片外 `public-prior.ts`）：每调用
   重校验整个快照 + 逐 source×catalogId×row×alias 的 trim/toLowerCase。
2. **真实规模下 prior 面仍是 µs 级**：live face 每批从 130–136 µs 抬到
   211–330 µs，深低于落地线。今日矩阵所有有流量的格全部带内，切片收口
   结论不因盲区闭合而改变。
3. 该格为 S12-B-2 的裁决提供了两端锚点（§4.2），并把切片的结构性重开
   条件收紧为可操作的一条：**任何 N≥10³ 调用方开始传 prior**（§7）。

## 4. 关键裁决细节

### 4.1 S12-B-1：等价完美，输在与 S11-B-1 同族的「肥目录」机制

等价论证一行即完备：两种成员结构在同一元素序列上的判定逐点相同（均
SameValueZero），过滤循环其余逐字节未动。fuzz 特意保留 20% 重复
allowed id 试炼（S6-B-5 长度守卫的击杀形状）与混大小写 id，全部逐位。

基准淘汰机制清晰且与 S11-B-1 呼应：省掉的是每 route 一次的 Set 构造
（M=2 时 ~35–70ns，S6-B-5 曾锚定），付出的是每 (model,route) 一次的
O(M) 逐元素扫描——M=2 时 4 次指针比较近零成本、净赚 µs 级；M=7 起
扫描期望 ~M²/2 次比较开始追平构造省费（符号翻转）；M=10 压力目录
多数轮为负。**「反索引在小目录赚微利、在肥目录倒贴」与 S11-B-1
「融合在肥循环倒贴」互为镜像**，二者合并把 route() 主循环的
「结构选择」维度双向封死：现行 Set 形态恰是两个方向失衡点之间的
现状最优。即取 M=2 全正口径，+40~+413 µs/批仍在 S4-B-4（143–215 µs）
已裁决噪声带同阶。封死。

### 4.2 S12-B-2：全战役 B 切片首个「等价 + 全格符号稳定为正 + 假设规模越线」仍被真实规模否决的候选

三重证据链全绿：(1) replicaCurrent 对真实 `assignTasks` 逐字节保真
（消除「测的不是生产语义」）；(2) replicaMemo 对 replicaCurrent 逐字节
（memo 本体等价）；(3) 无效快照首抛奇偶性（fail-closed 语义不因 memo

+13.7~+30.6 ms/批——若 eval-routing 传 prior，这是全战役 B 切片唯一
达到落地线的候选。

但验收线第 3 条的「真实规模」不可让渡：prior 流量面取证（§1）钉死

既有纪律，淘汰。落地设计成本一并记档（重开时即用）：memo 需经
(a) `pickPreferredModel` 加可选 memo 参数（公开签名扩展）、或
(b) 新导出批量变体（S7-I-1 有新导出先例）、或 (c) 在 `assign.ts` 复制

function mulberry32(seed: number): () => number {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) >>> 0;
    let t = a;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

function resolveReplica(input: RouteTaskInput): ResolvedReplica {

interface PartitionOutcome {
  readonly eligible: readonly CatalogModel[];
  readonly refusals: readonly RoutingRefusal[];
}
/** Faithful replica of today's partitionLiveCandidates (per-route Set). */
function partitionSetBased(
  models: readonly CatalogModel[],
  input: RouteTaskInput,
  resolved: ResolvedReplica
): PartitionOutcome {
  const allowed = new Set(input.modelPolicy.allowedModels);
  const eligible: CatalogModel[] = [];
  const refusals: RoutingRefusal[] = [];
  for (const model of models) {
    if (!allowed.has(model.id)) continue;
    const checkResult = evaluateLiveCandidate(model, {
      role: input.role,
      complexity: input.complexity,
      taskFamily: resolved.family,
      privacyRequired: resolved.privacyRequired,
      requiredCapabilities: resolved.requiredCapabilities,
      contextNeeded: resolved.contextNeeded,
      outputNeeded: resolved.outputNeeded,
      budgetUsd: resolved.budgetUsd,
      deadlineMs: resolved.deadlineMs,
      highRisk: resolved.highRisk,
      fixedCostUsd: model.estimatedCostUsd,
      fixedLatencyMs: model.estimatedDurationMs
    });
    if (checkResult.eligible) {
      eligible.push(model);
    } else {
      refusals.push(...checkResult.failures);
    }
  }
  return { eligible, refusals };
}

 * call site. pickFromPublicPrior(snapshot, family, pool) revalidates the whole
 * snapshot and recomputes blended quality on EVERY call; within one
 * assignTasks batch (snapshot, pool) are invariant and family has <= 8 values,
 * so N tier-3 calls collapse to <= 8. Memo stores only the picked modelId
 * string (or undefined), so no object identity can leak; the first tier-3
 * consult still performs the full validation (invalid snapshots throw at the
 * same task index with the same message).
 * Replica chain: (1) replicaCurrent must be byte-identical to the real

 * ============================================================ */
const DEFAULT_LIMITS: RoutingLimits = { remainingTimeMs: Number.MAX_SAFE_INTEGER };
function pickPreferredMemo(
  plan: AssignmentPolicyPlan,
  task: { readonly preferPrimary: boolean; readonly family: TaskFamily },
  prior: PublicPriorSnapshot,
  memo: Map<TaskFamily, string | undefined>
): string {
  if (plan.catalogIds.length === 1) return plan.catalogIds[0]!;
  if (task.preferPrimary && plan.primaryPreferredId !== undefined) {
    return plan.primaryPreferredId;
  }
  let picked: string | undefined;
  if (memo.has(task.family)) {
    picked = memo.get(task.family);
  } else {
    picked = pickFromPublicPrior(prior, task.family, plan.assignableModels)?.modelId;
    memo.set(task.family, picked);
  }
  if (picked !== undefined) return picked;
  return plan.cheapestAssignableId;
}
