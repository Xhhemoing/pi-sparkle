## 3. 关键裁决细节

### S11-D-1：rollback 身份守卫——校验域可证死，可达域 fail-closed 活闸

**候选主张。** `registry.rollback()` 的步骤链是：(1)
`versionsById.get(targetVersionId)`；(2) `resourceIdentityKey(input.identity)`
定位桶；(3) 桶成员检查 `knownTargets.some(v => v.versionId === target)`；
(4) `!identityEquals(target.identity, input.identity)` 抛
`DomainValidationError`。主张：步骤 3 通过后步骤 4 恒假——
`resourceIdentityKey = kind + "|" + name + "|" + scopeKey` 中 kind 是
无管道枚举、scopeKey 是 `"user-global"` 或 `"project:" + prj_ 格式 id`，
若编码单射则「同桶 ⇒ 同身份」，守卫是死码，可省一次深比较。
这不是 S9-D-3 的换名：S9-D-3 是 preparePromotion 内**同对象二次比较**
的死码性；本条是 rollback 内**跨对象身份编码单射性**，结构位与论证
机制均不同，铸新 ID 成立。

**单射性边界（理论门裁决）。** 编码在**parse 校验域**上确实单射：
`loadAdaptationRegistry → parseRegistrySnapshot → parseScope` 强制
`isProjectId`（`^prj_[a-z0-9]+$`，无管道），name 虽可含 `"|"` 但
name 是键中最后自由段前的段——两个身份若 kind、scopeKey 均合法，
键相等 ⇔ 三段逐段相等 ⇔ `identityEquals`。fuzz 用带 `"|"` 的 name
（`"n|project:prj_x"`、`"a|b"`）专门攻击这一点，200 组（含跨身份
目标、陈旧期望指针、未知目标、已退休目标、幂等 no-op、degradation
提案路径）**守卫零触发**，孪生 A（逐字复刻）与真 `registry.rollback`
逐位同判、孪生 B（去守卫）与孪生 A 在校验域逐位等价（3/3 运行）。

**但可达域更大（反例）。** `ResourceRegistry.fromSnapshot` 与
`registerBaseline` 是**公开导出面**，二者对 `scope.projectId`
**不做任何格式校验**（复读 registry.ts 与 resource.ts 确认：projectId
只在 domain/ids.ts 的 `createProjectId`/`parseScope` 处校验，内存路径
绕过）。构造：

```text
identityA = { kind:"prompt", name:"n",           scope:{ project, projectId:"a|project:c" } }
identityB = { kind:"prompt", name:"n|project:a", scope:{ project, projectId:"c" } }
⇒ 两键均为 "prompt|n|project:a|project:c"，identityEquals(A,B)=false
```

经 `fromSnapshot` 注入后对 identityA 发起 targetVersionId=vB 的
rollback：**现行代码 fail-closed**（`rollback target rsv_colB0001 does
not match requested identity`，3/3 运行）；**去守卫孪生 fail-open**——
跨身份 CAS 回滚落地，identityA 的活跃指针指向 identityB 的版本
（3/3 运行）。即：步骤 3 的桶成员检查在键碰撞下无鉴别力，守卫是
**唯一**挡住跨身份回滚的闸门。消除它即违反 fail-open 禁区（X1-1 族
精神）与 CAS 契约（「期望→目标」必须在同一身份内）。把守卫前移或
改为在 fromSnapshot/registerBaseline 处校验 projectId = 收紧公开输入
契约 = 行为变更（拒绝现在被接受的输入），超出优化职权（X0-4 族），
且不减少任何路径的工作量。

**收益门（独立第二杀）。** 即便理论门放行：common path 上一次
`identityEquals`（对象浅比较 + scope 判别）实测 5.27–9.32 ns，rollback
op 锚 3.1–5.6 µs，配置态整命令地板 ≥2.2 ms——上界比落地线低约
**五个数量级**。纳秒级，指令明文 reject。

**判决：淘汰，铸 S11-D-1 入排除表。** 附带新知识：本反例把「守卫
死码可删」的裁决标准精确化为**必须在全部可达输入面（含内存公开面）
上证死**，parse 校验域证死不充分。这加固了 R9-D §S9-D-3 的「零成本
保留为防御纵深」路线。

### S11-D-2：装载链单遍融合——相位分解上界 72–74µs，机制撞 X1-2/X0-4

**候选主张。** `loadAdaptationRegistry` = readFile → JSON.parse →
`parseRegistrySnapshot`（构建中间已校验数组）→
`ResourceRegistry.restore/fromSnapshot`（把一切再迭代进 Map，重验 id、
按 S8-D-1 重哈希每 blob）。融合为私有单遍装载器可省中间快照数组与
一轮迭代。这不是 S1-D-5（`Array.from(values())` 改直接迭代，常数噪声）
的换名——那是快照**导出**侧的单点迭代形态；本条是**装载**侧跨两函数
的整链融合，结构位不同，铸新 ID 成立。

**相位分解（收益门裁决，配置态 146.2KB registry.json）。** 三次运行：

| 相位 | 耗时 | 融合可及？ |
| --- | --- | --- |
| readFile | 182–227 µs | 否（I/O 不变） |
| JSON.parse | 106–112 µs | 否（仍需全量解析） |
| parseRegistrySnapshot | 42–46 µs | 是 |
| restore（fromSnapshot，含重哈希） | 159–167 µs | 部分 |
| —— 其中 blob 重哈希单独 | 128–138 µs | 否（S8-D-1 必须保留） |
| 实测整 load | 521–578 µs | — |

融合收益上界 = parse + (restore − rehash) = **72–74 µs/load**；实际
严格更小（融合体仍须逐字段执行 parse 与 restore 的全部 fail-closed
校验，只省数组物化与循环开销本身）。每 CLI 命令恰一次装载（§1c），
一次性 <75µs，比落地线低约三个数量级。**收益门单杀。**

**机制门（第二杀，记录在案）。** 落地形态只有两种：(a) 新私有融合
装载器与现行 `parseRegistrySnapshot`+`fromSnapshot` 并存——两份
fail-closed 校验逻辑并行演化，任何一处更新遗漏即静默分叉 = X1-2
（fail-closed 校验器的并行实现）族；(b) 改 `parseRegistrySnapshot` /
`fromSnapshot` 公开签名合并二者 = X0-4 族。均为既有禁区机制。

**判决：淘汰，铸 S11-D-2 入排除表。**

function mulberry32(seed: number): () => number {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) >>> 0;
    let t = a;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

      evaluationPlan: EVAL_PLAN

    const entry: { identity: ResourceIdentity; v1: ResourceVersion; v2?: ResourceVersion } = { identity, v1 };
    if (i < 5) {
      const result = promoteWithRegistry(registry, {
        candidateId: candidate.candidateId,
        expectedCurrentVersionId: v1.versionId,
        content: `${body}\n## amendment ${i}\nAdd an explicit check for the attributable failure.\n`,
        approvedBy: HUMAN,
        review: mkReview(candidate.candidateId, candidate.contentHash, `${tag}p${i}`),
        changeNote: mkNote(`prompt:${tag}${i}`, v1.versionId),
        explicitApproval: true
      });
      entry.v2 = result.newVersion as ResourceVersion;
    } else if (i === 5) {
      registry.beginPromotion({
        candidateId: candidate.candidateId,
        expectedCurrentVersionId: v1.versionId,
        content: `${body}\n## amendment ${i}\nAdd an explicit check for the attributable failure.\n`,
        approvedBy: HUMAN,
        review: mkReview(candidate.candidateId, candidate.contentHash, `${tag}p${i}`),
        changeNote: mkNote(`prompt:${tag}${i}`, v1.versionId),
        explicitApproval: true
      });
    }
    versions.push(entry);
  }
  const first = versions[0] as { identity: ResourceIdentity; v1: ResourceVersion; v2?: ResourceVersion };
  registry.rollback({
    identity: first.identity,
    expectedCurrentVersionId: (first.v2 as ResourceVersion).versionId,
    targetVersionId: first.v1.versionId,
    reason: "degradation",
    evidence: ["ev:configured-degradation"],
    automatic: false

    targetVersionId: second.v1.versionId,
    reason: "user",
    evidence: ["ev:configured-user"],
    automatic: false
  });
  registry.retire((versions[2] as { v1: ResourceVersion }).v1.versionId);
  registry.retire((versions[3] as { v1: ResourceVersion }).v1.versionId);
  return built;
}

/* ============================================================
 * S11-D-1: registry.rollback() identityEquals guard elision.
 *
 * Claim under adjudication: after step 3 (bucket membership in
 * versionsByKey[resourceIdentityKey(input.identity)] passes), the guard
 * `!identityEquals(target.identity, input.identity)` at registry.ts:245 is
 * provably dead, because resourceIdentityKey = `${kind}|${name}|${scopeKey}`
 * with a "|"-free kind (enum) and a "|"-free scopeKey ("user-global" or
 * "project:" + pattern-valid prj_ id) is an injective encoding on the
 * parse-validated domain (loadAdaptationRegistry -> parseScope enforces
 * isProjectId).
 *
 * Counter-claim: the in-memory library surface (ResourceRegistry.fromSnapshot
 * and registerBaseline) never validates scope.projectId, so a projectId
 * containing "|" is representable, the encoding loses injectivity, and two
 * DISTINCT identities can share one bucket. The guard is then the only gate
 * between bucket-membership and a cross-identity CAS rollback (fail-open).
 *
 * Twin A = verbatim replica of the rollback prefix + CAS; twin B = guard
 * removed. Fidelity of twin A is checked against the REAL registry.rollback.
 * ============================================================ */
interface TwinState {
  versionsById: Map<string, ResourceVersion>;
  versionsByKey: Map<string, ResourceVersion[]>;
  activeByKey: Map<string, string>;
  retired: Set<string>;
  log: { kind: string; from: string; to: string; reason: string }[];
}
function twinAddVersion(state: TwinState, version: ResourceVersion): void {
  state.versionsById.set(version.versionId, version);
  const key = resourceIdentityKey(version.identity);
  const existing = state.versionsByKey.get(key) ?? [];
  state.versionsByKey.set(key, [...existing, version]);
}
function mirrorFromSnapshot(snapshot: ResourceRegistrySnapshot): TwinState {
  const state: TwinState = {
    versionsById: new Map(),
    versionsByKey: new Map(),
    activeByKey: new Map(),
    retired: new Set(),
    log: []
  };
  for (const version of snapshot.versions) twinAddVersion(state, version);
  for (const id of snapshot.activeVersionIds) {
    const version = state.versionsById.get(id) as ResourceVersion;
    state.activeByKey.set(resourceIdentityKey(version.identity), version.versionId);
  }
  for (const id of snapshot.retiredVersionIds ?? []) state.retired.add(id);
  return state;
}
/** Verbatim replica of registry.rollback (validateRollbackInput elided: the
 *  fuzz only feeds inputs that pass it, mirroring the real call). withGuard
 *  toggles the registry.ts:245 identityEquals guard. instrument counts guard
 *  evaluations that would fail after step 3 passed. */
function twinRollback(
  state: TwinState,
  input: RollbackInput,
  withGuard: boolean,
  instrument?: { guardWouldFire: number }
): { ok: boolean; active: ResourceVersion } {
  const target = state.versionsById.get(input.targetVersionId);
  const key = resourceIdentityKey(input.identity);
  const knownTargets = state.versionsByKey.get(key) ?? [];
  if (
    target === undefined ||
    !knownTargets.some((version) => version.versionId === input.targetVersionId)
  ) {
    throw new DomainValidationError(`unknown rollback target: ${String(input.targetVersionId)}`);
  }
  if (instrument !== undefined && !identityEquals(target.identity, input.identity)) {
    instrument.guardWouldFire += 1;
  }
  if (withGuard && !identityEquals(target.identity, input.identity)) {
    throw new DomainValidationError(
      `rollback target ${target.versionId} does not match requested identity`
    );
  }
  if (state.retired.has(input.targetVersionId)) {
    throw new DomainValidationError(
      `version ${input.targetVersionId} is retired and cannot receive new assignments`
    );
  }
  const activeId = state.activeByKey.get(key);
  const active = activeId === undefined ? undefined : state.versionsById.get(activeId);
  if (active === undefined) {
    throw new DomainValidationError(
      `unknown expected version: ${String(input.expectedCurrentVersionId)}`
    );
  }
  if (active.versionId === input.targetVersionId) {
    return { ok: true, active };
  }
  if (input.reason === "degradation" && input.confirm !== true) {
    const last = state.log.at(-1);
    const alreadyProposed =
      last !== undefined &&
      last.kind === "rollback-proposed" &&
      last.from === active.versionId &&
      last.to === input.targetVersionId &&
      last.reason === "degradation";
    if (!alreadyProposed) {
      state.log.push({
        kind: "rollback-proposed",
        from: active.versionId,
        to: input.targetVersionId,
        reason: "degradation"
      });
    }
    return { ok: false, active };
  }
  const current = state.activeByKey.get(key);
  if (current === undefined) {
    throw new DomainValidationError(
      `unknown expected version: ${String(input.expectedCurrentVersionId)}`
    );
  }
  if (current !== input.expectedCurrentVersionId) {
    throw new DomainValidationError(
      `CAS failed: active version ${current} does not match expected ${input.expectedCurrentVersionId}`
    );
  }
  state.activeByKey.set(key, input.targetVersionId);
  const restored = state.versionsById.get(input.targetVersionId) as ResourceVersion;
  state.log.push({
    kind: "rolled-back",
    from: input.expectedCurrentVersionId,
    to: input.targetVersionId,
    reason: input.reason
  });
  return { ok: true, active: restored };
}

    return `ok:${String(result.ok)}:${result.active.versionId}`;
  } catch (error) {
    return `err:${(error as Error).message}`;
  }
}
