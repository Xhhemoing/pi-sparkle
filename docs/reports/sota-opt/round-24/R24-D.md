## 2. 新轴：批准权限面——自动提升模式 × 预算态（组件账 + 模式对偶 + 计数器剂量 + 见证）

方法：二十三遍的命令类矩阵把 promote 当作**单形态命令**——全部
成功夹具都是 explicit 人工批准 + 默认 profile，于是批准子系统
（approval-profile.ts 全文件 + promotion-rules.ts
assertExplicitApprovalActor + registry.ts L608-619 门链 +
L444-446 计数器）只在「恒假/拒绝」形态上有价：R22-D 的
canAutoPromote per-op 价测的是内建 profile 的 always-false 短路，
R17-D 的拒绝终端测的是 explicitApproval:false 的抛错路径。规格内
**唯一未走过的成功命令类**——opted-in profile 下的 auto 提升——
与**唯一未剂量过的持久化标量**——autoPromotionsUsed——构成本轮
的完备性缺口。本轴分六段关死：(2a) 理论——模式差的三组件结构
上界与预算腿的 O(1)/O(digits) 结构；(2b) 组件 ns 账；(2c) 模式
对偶 + 语义等价见证；(2d) 预算态剂量 + 字节边际；(2e) 边界迁移 /
中程持久化 / 守卫见证；(2f) 10 ms 越线求解与天花板裁决。判读标尺
沿用历轮验收线（数十–数百 ms 稳态；µs/ns 与 once-per-run 是拒绝
类）。

### 2a. 理论:模式差的结构上界与预算腿的复杂度类

promote 门链（preparePromotion）在两模式间逐行对差恰得三个差异
组件：(i) `canAutoPromote` 真路径比假路径多走 includes 命中 +
预算整数比较（假路径在默认 profile 上于
`autoPromoteClasses.length === 0` 短路）；(ii)
`validateApprovalProfile` 对 opted 形态（1 类 autoPromoteClasses）
比默认形态（0 类）多一轮交叉 includes；(iii) usingAuto 跳过
explicit 闸内的 `assertExplicitApprovalActor`（10.8–11.8 ns）与
review-actor 一致性支路，且 auto 调用方自带 profile 时跳过 L608
的每 promote `createDefaultApprovalProfile()` 分配（S4-D-4/R13-D
属地）。门链其余全部——validateChangeNote、
validatePromotionReview、hash32×3、CAS、pendingVersion 物化、
台账追加——按构造模式不变。故 |模式差| 结构上界为三组件之和
（<150 ns/promote），S1b 对偶的任何超出部分是噪声带。预算腿：
`canAutoPromote` 对 count 的全部使用是单条
`autoPromotionsUsed < budget.maxAutoPromotions` 整数比较 ⇒ 对
count O(1)；持久化面是 snapshot 里一个 JSON number ⇒ O(digits)
字节。两个复杂度类都没有可越线的自变量。

### 2b. 组件 ns 账（S1a；三运行带；2×10⁵ reps/项）

| 组件 | 带（三运行） | 备注 |
| --- | --- | --- |
| canAutoPromote 假路径（默认 profile） | 19.7–23.1 ns | 生产每 promote 已在付的既有项 |
| canAutoPromote 真路径（opted，count<budget） | 28.5–29.3 ns | run3 61.9 为 PIC 离群（§7 诚实记录） |
| assertExplicitApprovalActor（human） | 10.8–11.8 ns | auto 跳过的 explicit 腿 |
| validateApprovalProfile（默认 0/3 类形态） | 95.2–102.5 ns | 两模式都付（L609 模式无关） |
| validateApprovalProfile（opted 1/3 类形态） | 134.6–147.6 ns | opted 形态差 39.4–45.1 ns |

模式差账：auto 加（真−假）7.2–9.6 ns + validate 形态差 39.4–45.1
ns，减 actor assert 10.8–11.8 ns 与默认 profile 每 promote 分配
（S4-D-4 属地，R15-D 已价分配/GC 面）⇒ 净 |Δ| 钉死在数十
ns/promote，与 2a 结构上界一致。

### 2c. 模式对偶（S1b；孪生舰队；见证先行）

见证（每次运行全过）：W1 双臂终态 canonical 相等——**除恰好
`autoPromotionsUsed` 一个字段**（auto 臂 = N、explicit 臂 = 0；
掩蔽该字段后逐字节相等），auto 臂全部 candidate 落 approved、
active 指针逐身份离开 v1、pending 双双清零；W2 auto 臂双运行确定
性（canonical 逐字节相等）；配置态对偶中 auto 臂预算消费恰 1、
explicit 臂恰 0。

| 格 | explicit 臂 | auto 臂 | Δ(auto−explicit) |
| --- | --- | --- | --- |
| N=64 舰队全程 | 0.30–0.31 ms | 0.30–0.31 ms | −0.00 至 −0.01 ms（−66 至 −112 ns/promote） |
| N=2048 舰队全程 | 14.04–15.30 ms | 13.36–13.96 ms | −0.13 至 −1.84 ms（−65 至 −901 ns/promote） |

(iii) N=2048 的 Δ 带宽（−0.13 至 −1.84 ms）本身横跨一个数量级，
是 min-of-reps 噪声带而非稳定收益。

### 2d. 预算态剂量（S1c；count ∈ {0, 4096, 1048576}）

预置计数器（snapshot 补丁 + `ResourceRegistry.fromSnapshot`
restore，恰为持久化恢复的生产链路）后各跑 512 次 auto-promote
（预算 = preCount + 512 + 1，全程为真路径）；同长 id tag
（bda/bdb/bdc）隔离 id 字节，使文件对比中唯一的意图字节差是
计数器数字位：

| 预置 count | 512 次 auto-promote | µs/op | registry.json |
| --- | --- | --- | --- |
| 0 | 3.47–4.83 ms | 6.78–9.42 | 1844.7 KB |
| 4096 | 4.39–5.24 ms | 8.57–10.24 | 1844.7 KB |
| 1048576 | 3.58–4.36 ms | 7.00–8.52 | 1844.7 KB |

三运行中 count=1048576 腿**均为最快**，序随抖动翻转 ⇒ 剂量响应
结构平坦（O(1) 整数比较，2a 理论直接命中）。计数器持久化字节
边际：file(1048576+512) − file(0+512) = **恰 4 字节**（"1049088"
7 位 − "512" 3 位；数字位以外零字节差）——O(digits) 结构实证。
每档 save/load 往返后计数器保真（preCount+512）。

function mulberry32(seed: number): () => number {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) >>> 0;
    let t = a;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

/** Recursively sort object keys so JSON compare ignores key order. */
function canonicalJson(value: unknown): string {
  return JSON.stringify(value, (_key, val: unknown) => {
    if (val !== null && typeof val === "object" && !Array.isArray(val)) {
      const sorted: Record<string, unknown> = {};
      for (const k of Object.keys(val as Record<string, unknown>).sort()) {
        sorted[k] = (val as Record<string, unknown>)[k];
      }
      return sorted;
    }
    return val;
  });
}

function autoProfile(budget: number): ApprovalProfile {
  return {
    profileId: "apr_r24d-auto",
    profileVersion: 1,
    defaultMode: "proposal-first",
    autoPromoteClasses: ["prompt"],
    neverAutoPromote: [...NON_AUTO_PROMOTABLE_KINDS],
    budget: { maxAutoPromotions: budget }
  };
}

interface FleetRow {
  readonly identity: ResourceIdentity;
  readonly v1: ResourceVersion;
  readonly candidate: ImprovementCandidate;
  readonly input: PromoteInput;
}

interface Fleet {
  readonly registry: ResourceRegistry;
  readonly rows: readonly FleetRow[];
}

/** N distinct prompt identities, each with a baseline and one candidate.
 * All PromoteInput objects are prebuilt so timed regions contain only
 * registry calls. Same tag => identical deterministic id streams; the
 * `mode` changes ONLY the input flags (explicitApproval / approvalProfile),
 * never the identities, contents, or id consumption. */
function buildPromptFleet(tag: string, n: number, mode: "explicit" | "auto", approvedBy: AuthorIdentity = HUMAN): Fleet {
  const registry = new ResourceRegistry({ now: () => NOW, generateId: sequentialIds(tag) });
  const profile = mode === "auto" ? autoProfile(n) : undefined;
  const rows: FleetRow[] = [];
  for (let i = 0; i < n; i += 1) {
    const identity: ResourceIdentity = {
      kind: "prompt",
      name: `fleet-prompt-${i}`,
      scope: { kind: "project", projectId: createProjectId(() => `${tag}proj`) }
    };
    const body = `# fleet prompt ${i}\nKeep the diff bounded to the stated scope and cite evidence for every claim (row ${i}).\n`;
    const v1 = registry.registerBaseline({ identity, content: body, author: HUMAN });
    const content = `${body}\n## amendment\nAdd an explicit check for the attributable failure (row ${i}).\n`;
    const candidate = registry.createCandidate({
      identity,
      content,
      parentVersionId: v1.versionId,
      author: HUMAN,
      evaluationPlan: EVAL_PLAN
    });
    const input: PromoteInput = {
      candidateId: candidate.candidateId,
      expectedCurrentVersionId: v1.versionId,
      content,
      approvedBy,
      review: mkReview(candidate.candidateId, candidate.contentHash, `${tag}${i}`),
      changeNote: mkNote(`fleet:${tag}${i}`, v1.versionId),
      explicitApproval: mode === "explicit",
      ...(profile !== undefined ? { approvalProfile: profile } : {})
    };
    rows.push({ identity, v1, candidate, input });
  }
  return { registry, rows };
}

function runFleet(fleet: Fleet): number {
  const t0 = performance.now();
  for (const row of fleet.rows) {
    promoteWithRegistry(fleet.registry, row.input);
  }
  return performance.now() - t0;
}
