## 2. 新轴：I/O 文本编解码拓扑 / 每 run 转码字节清单面

### 2.1 定义与盲区

受控变量：**切片 fs 文本编解码位点的数量与位置、一次收集运行逐腿
支付的编解码调用数与转码字节数（双仿射清单及其相互独立性）、导出面
的编解码域归属（前编解码 Buffer 域 / 后编解码 UTF-16 域）、以及
剥离所包裹 I/O 后纯编解码机器的价格**。切片内 fs 文本编解码位点
普查（`rg '"utf8"' src/learning/` + 逐 I/O 腿委托追踪）：恰 **3
处**——`auto-loop.ts:236`（`readFile(join(dir,name), "utf8")` 的
utf8 **解码**，ingest 腿）、`bandit-store.ts:14`（`readFile(path,
"utf8")` 的 utf8 **解码**，bandit 读）、`bandit-store.ts:80`
（`writeFile(path, string, "utf8")` 的 utf8 **编码**，bandit 写）。
其余全部 I/O 到达面（registry load/save、feedback append、文件锁）
的编解码发生在姊妹属地源文件里（C1 委托表）。

盲区论证（为何 31 轮从未受控）：R16-E 的文本字节剂量轴在其定义段
明确「JSON.parse/readFile 的 I/O 面按 S1-E-5 排除，只测切片内
CPU」——它剂量的是**已解码字符串**进入 CPU 函数后的成本，编解码器
本身从未在受控变量里；R18-E 的字符宽度剂量走 regex/truncate 后解码
管道，同样后编解码；R30-E 对完全相同的 I/O 腿数的是 promise 分配
（悬挂机器），R29-E 数的是壁钟采样（时钟机器）——三台机器（promise
/ clock / codec）共享宿主腿但物理对象两两不同；R29-I（I 属地）拥有
输入文件的 JSON 序列化**形态**、R29-J CSPELL（J 属地）拥有持久物
**内容拼写**——两者决定字节**总量**，但「字节如何被转码、转码调用
落在哪、机器费多少」不属于任何一轮。本轴的可观测量（打补丁
`Buffer.prototype.toString` 计调用与 this.length 字节、`Buffer.from`
计字符串编码调用——`fs.promises.readFile(path, "utf8")` 在两引擎上
恰付一次该 toString，probe 见证）在 31 轮所有 E 报告中零出现。

### 2.2 与近邻轴的区分（换名自查核心）

- **vs R16-E 文本字节 CPU 剂量**：R16-E 给后解码字符串的 CPU 消费
  定价、I/O 面明示排除；本轴恰恰只测被它排除的 fs 边界编解码器，
  且以调用清单 + 字节清单双账本受控。物理对象不同（CPU 扫描 vs
  字节转码），无重合测量。
- **vs R18-E 字符宽度 / 执行层级**：宽度决定「每字符几字节」——
  是本轴的**杠杆**不是变量（p1w 仅一个 CJK 见证，宽度剂量属
  R18-E）；R18-E 从未数过编解码调用或字节。
- **vs R30-E 悬挂清单面**：宿主腿相同、机器不同——promise 分配数
  与转码字节数是两个独立可观测量（空 .json：悬挂 1 次/名 = 解码
  调用 1 次/名，但解码字节 = 0——调用账本按名重合、字节账本唯本轴
  独有，C2 蓄意不对称阶梯）；R30-E 的 415 inits 常数对字节全盲。
- **vs R29-E 时钟清单面**：计费基不同（1 采样/**解析成功**记录 vs
  1 解码/.json **文件名**）——malformed/empty .json 付解码不付
  时钟采样；仅引作不对称对照，不移植。
- **vs R29-I serialization-form face（I 属地）**：形态决定字节
  总量，是杠杆；本轴在固定形态下数调用与字节，形态剂量不做。
- **vs R29-J CSPELL（J 属地）**：CSPELL 是持久**物内容**的字节缝；
  本轮 C4(c) 的 "utf8" 拼写观察是**源码级**别名等价（行为逐位
  相同、零成本差），只读记录，不因撞「拼写」词根补铸。
- **vs R28-J ZREP**：ZREP 是 store 零态**来源**；本轴 C3 的
  「ENOENT 腿编解码器从未被调用」是同一腿上的编解码边界事实，
  不触零态语义。
- **vs R30-J LINKTOP**：编解码发生在 referent 解析之后，对链接
  拓扑全盲；不移植。
- **vs R31-A injected-callable plane（停放门）**：本轴器械是
  harness 级 Buffer 补丁（测量窗内启用、定价段关闭、等式断言使
  harness 常数相消），未向生产注入任何可调用物；不重开该门。
- **vs R31-B 六扇停放门**：全部是 B 区 live 路由缝（catalog 行

  in-B / prior 别名通路），与 E 切片 fs 编解码无共享物理对象。
- **vs R31-D 属地格（快进合入）**：drift-monitor analysis-window

  零 drift-monitor 触点；不移植。
- **vs R31-C ambient intrinsic-binding / intrinsic-resolution face
  / BINDX（收稿快进合入）**：BINDX 以 realm 级内建绑定态为受控
  变量剂量（C 属地，capture-hoist 实尺度决斗）；本轴的 Buffer 补丁

async function codecDelta(fn: () => Promise<unknown>): Promise<{ dec: number; bytes: number; enc: number }> {
  enableHook();
  const d0 = decodeCalls;
  const b0 = decodeBytes;
  const e0 = encodeCalls;
  await fn().catch(() => undefined);
  const out = { dec: decodeCalls - d0, bytes: decodeBytes - b0, enc: encodeCalls - e0 };
  disableHook();
  return out;
}
function codecDeltaSync(fn: () => unknown): { dec: number; enc: number; value: unknown } {
  enableHook();
  const d0 = decodeCalls;
  const e0 = encodeCalls;
  const value = fn();
  const out = { dec: decodeCalls - d0, enc: encodeCalls - e0, value };
  disableHook();
  return out;
}
