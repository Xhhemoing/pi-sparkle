## 2. 第三十一遍枚举：持久工件访问权限 / inode 元数据模式拓扑面（MODEX，六腿 25 计时格 × 九类见证）→ 全部「无候选」→ 诚实空结果

### 2.1 轴定义与战役首创性（非重铸论证 + 弃选候选普查）

**面定义。** 持久工件 inode 上的**访问权限字**（模式位）与其父
目录 inode 上的权限字：内核在切片每一次 open / stat / unlink /
truncate 进入工件前必须先清的授权门。剂量空间：文件模式
{0644, 0600, 0640, 0664, 0444, 0400, 0000} × 目录模式
{0755, 0700, 0500, 0555}，以显式 chmod 铸后下达。

**战役首创性（预铸三问）。**
1. **独立物理层**：模式字住在 inode 元数据里，与名字文本
   （R28-I）、名字→inode 绑定（LINKTOP）、内容字节（CSPELL）、
   零态表征（ZREP）、编解码（R31-E）、API 形态（R13-J）物理上
   两两不同层——同一工件可以在任何绑定/字节/名字组合下取任意
   模式字。W-7d 给出可分辨性直证：同一缝（双探针载入）上模式
   坐标与绑定坐标触发**相反的门**。
2. **生产通量**：切片每条 I/O 腿的每次 syscall 都过权限门（通量
   = 每命令数次–数十次）；生产写手以 0666&~umask / 0777&~umask
   铸造且**永不**显式设置（W-9 动词铸造普查 + 29 文件 grep 零
   chmod / 零 mode 实参 / 零 umask / 零八进制字面量——全库 chmod
   仅切片外 file-credential-store L104 一处）。
3. **从未受控**：历轮全部夹具在默认 umask 下铸盘、进程 euid 持有
   一切 inode——模式字在 R1-J..R30-J 的每个家族里恒为 0644/0755，
   从未当过受控变量。语料 grep 复核：`chmod|umask|EACCES|0o` 在
   历轮 J 报告中仅两类命中——R28-I 附录夹具的 chmodSync 0o755
   （I 区 npm `.bin` shim 铸造工序，非剂量变量）与 R13-J 位点
   A/B 的「EACCES 两侧同码」**理论论证**（探针合并拒绝的原理性
   反例，坐标本身从未下剂）。MODEX 名未被占用。

**非重铸划界（逐禁令）。**
- ≠ **外部存储拓扑**（J-local 禁令）：对象是 state root 内部
  工件 inode 的元数据字，不触挂载点/设备/后备文件系统类型。
- ≠ **LINKTOP**：绑定逐臂钉死直接普通文件 nlink=1（逐臂断言）。
- ≠ **CSPELL / ZREP / SIDEC**：字节账户 40600 / 363 / 11484 全臂
  钉死；全臂在位非空；侧车存量 T=20 规范 pretty。
- ≠ **R13-J**（API 形态）：调用形态钉死生产原形；R13-J 的 EACCES
  文本是拒绝探针合并的理论论证——本轴把那两个理论不对称第一次
  变成**受控剂量下的经验见证**（W-7a/W-7d），并新增五个从未成文
  的授权账户。
- ≠ **R17-J**（拒绝路径普查——代码侧对非法输入类的拒绝端点，非
  内核授权门）；≠ **R18-J**（skip 普查——吞取端点定价：本轴是
  「第三个 errno 类抵达同一批已定价端点」，端点本体零重提）。
- ≠ **R25-I**（进程环境坐标）：umask 钉死 0022 断言、剂量以
  chmod 直接下在工件 inode 上——物理对象是 inode 模式字，不是
  环境变量。
- ≠ **R5-J 错误面契约**：全部包络见证是 as-built 普查、零行为
  变更提案；fail-open 族保持关闭。

**弃选候选普查（枚举过程中逐一否决，卸证明负担）。**
1. **libuv 线程池饱和 / 排队延迟**：物理上区别于 R16-J SYSCENSUS
   的每操作机械成本（排队等待是另一量），但三重否决——(i) 生产
   占空比为零：`src/` Promise.all 普查仅 `src/run/`（supervisor
   L431 / flowchart-run L268 / coordinator L497）对**任务句柄**
   并发等待、切片全部 I/O 腿串行 await（已闭 Promise.all 族
   S2-J-10 / S4-J-2/3 / S5-G-5 / S6-G-5 / S7-I-3 / S7-G-5 把池
   占用钉在 1，本普查回头加固了那些拒绝）；(ii) 池宽
   UV_THREADPOOL_SIZE = 进程环境坐标（R25-I）/ 引擎参数
   （S5-I-5 切片外裁决）；(iii) 响应是宿主争用倍率、切片代码无
   可作用杠杆。
2. **fd 表占用**：资源表剂量在生产 fd 数（个位）下 µs 级平坦、
   零生产通量。
3. **目录条目基数**：外部存储拓扑禁令毗邻 + 切片零 readdir 消费
   缝 + 生产规模下量级失败。
4. **文件系统后备类型 / 挂载拓扑**：执行基底所有权、切片外 +
   禁令域。
5. **extent 布局 / 稀疏度**：生产写手无控制权、量级噪声级。
6. **codeMapTokenBudget 配置面**：µs 级平坦、once-per-session、
   按 R31-D 先例归既有所有权。
7. **模块单例跨 configure 携带态**：数组重赋值同价、
   once-per-process ns–µs 级。
8. **inode 时间戳（mtime/atime）**：切片零读取方，剂量语义惰性。

### 2.4 裁决

**六腿全部「无候选」。** 三重收口：

1. **生产只能铸造 0644/0755 臂（mint-default-arm）**：W-9 动词
   铸造普查直证 appendJsonlLine（mkdir+appendFile）与 saveToDisk
   （mkdirSync+writeFileSync）在 umask 0022 下铸 0644 文件 /
   0755 目录；切片 29 文件零 chmod / 零 mode 实参 / 零 umask /
   零八进制字面量 ⇒ 模式坐标完全由进程 umask 继承、代码侧无
   控制点；全部外来模式仅能由外部动作铸造；且控制臂与任何限权臂
   在每条缝上测不出差异——「让缝更快」没有生产侧剩余动作。
2. **代码侧改形全部撞已闭族**：铸盘 chmod 收紧（0600 加固）=
   每铸多一次 syscall、实测零性能收益、且属安全策略行为变更
   （切片外 file-credential-store L104 已持有 0600 加固形态的
   所有权，credentials 契约不动）；读写前 access() 预探 = R13-J
   API 形态已闭 + 位点 A/B 探针裁决原文（「无健全单调用等价
   形态」）；catch EACCES 软化任何缝 = fail-open 族保持关闭
   （R5-J 错误面契约：fail-open→fail-closed 与其逆向都是行为
   变更）；umask 下剂 = R25-I 进程环境坐标、切片外。
3. **量级**：授权区全格 µs 带内平坦（内核权限检查对任意模式字
   O(1)）；拒绝区是错误包络、不是计时格；距 tens-of-ms 落地线
   3–4 个数量级。

**五条语义普查事实随轴入档（as-built，proposal-first 观察，零产
码改动）：**

- **(a) EACCES 跨缝不对称——第三错误来源类**：模式 0000 的
  records.jsonl 上 `readFeedback` 抛裸 EACCES fail-closed
  （jsonl.ts L29 catch 只赦 ENOENT），级联经 deletion.ts L108
  catch-all 吞为 [] 且零写。继 LINKTOP W-7a（ELOOP：解析失败）、
  CSPELL W-7b（内容损坏）之后，同一缝不对称第三次以全新错误
  来源类（授权拒绝）复现——不对称是缝的性质，不是错误类的性质。
- **(b) 级联内双读门不对称**：同一 errno 类在 L108（catch-all）
  被吞、在 L111（`readFeedbackTombstoneIds` 只赦 ENOENT）致命
  裸抛；S5-J-3 钉死读序使该裸抛必然发生在任何写之前——0000 侧车
  上 MATCH 级联零盘面变异（W-7b 断言字节逐位未动）。
- **(c) 重写拒绝零变异 fail-closed**：0444 records 上 MATCH 级联
  在内存完成剥除后，`writeFeedbackRecords` 的 writeFile O_TRUNC
  在 open 即被拒（未及截断）；S6-J-1 串行两写（L121 先于 L124）
  保证侧车未被触碰——盘上无半态、内存计算量丢弃（W-7c 断言两
  文件字节逐位未动、模式仍 444）。
- **(d) 双探针载入门分岔——面独立直证**：模式 0000 的
  preferences.json **过** existsSync（F_OK 只需目录搜索权、不需
  文件读权——W-7d 直接断言 existsSync===true）、在 readFileSync
  裸抛 EACCES 出 `configurePreferencePersistence`；LINKTOP W-7c
  里 ELOOP 使 existsSync 返回 **false** → 静默武装空店、错误
  推迟到下一个写动词。同一缝、相反的门：模式坐标与绑定坐标物理
  可分辨 ⇒ 二面互不重铸。另 W-7e：0444 快照上写动词在内存 push
  与视图重建完成后裸抛——内存 51 / 盘上 50 半态（LINKTOP W-7c
  半态的模式坐标写照）。
- **(e) 授权来源三分账户**：**追加**权在文件 inode（0555 目录内
  对既存日志 appendFeedback 成功——mkdir recursive 对既存路径
  任意目录模式下静默成功、O_APPEND 只问文件）；**创建**权在目录
  inode（同一动词、同一目录模式、日志缺失 ⇒ 裸抛 EACCES、零
  物化）；**unlink** 权只在目录（W-8：0400 只读文件与 0644 删除
  账户逐位同一——removedPaths 相同、文件同样消失；W-7f：0555
  目录内 statExists 过、rm 裸抛 EACCES、removedPaths 全丢）；
  **改写**权只在文件（Leg D：D500 写禁父目录内全量 MATCH 级联
  成功且目录模式保留）。deletion / append / rewrite 三动词各问
  不同的 inode——这张授权地图是本切片错误包络的完备补全，历轮
  从未成文。

按纪律不铸任何 S31-J-\* ID；MODEX 记入本报告供父代理计划禁令，
**不写** EXCLUSIONS 表行。
