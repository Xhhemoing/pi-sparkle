## 3. 唯一残格的属主裁决：漂移监视器分析窗配置平面（不铸、不新停放）

**格的定义**：`createAdaptationDriftMonitor(options?: { windowSize?, calibrationDelta? })`（monitor.ts L48–59）的两参配置平面。R22-D S1a-4 的剂量网格只覆盖默认配置（windowSize=8, calibrationDelta=0.25）下的观测流长度 W∈{8,64,512}；windowSize / calibrationDelta 本身从未是受控变量——这是 §2 审计后 D 区仅存的未受控坐标。物理机制：每 observe 重付 `observations.slice(0, windowSize)` + `freezeBaseline`（4 个 Set 重建 + 均值）+ `slice(-windowSize)` + `evaluateWindow`（4 轴 majorityUnseen + 校准差）——全部 O(windowSize)；snapshot/restore O(累计观测 N)、`observations` 无界增长（R22-D 已钉）。

**铸轴前置证明（R31-A 同款三步，失败于第 1 步）**：

1. **独立物理对象 + 生产流量**：失败。生产调用方第三十一次 grep 复核为**零**（`rg "adaptation/(monitor|pareto|mutate|retirement|reflection)" src/ --glob '!src/adaptation/**'` 空匹配；切片外 adaptation importers 恰 cli/adapt.ts + learning 三文件（learned-routing / auto-loop / from-episode）+ tracking/analysis.ts 全 `import type`——R22-D 12/54 分拣原样成立）。配置平面不是新物理对象：windowSize 重标已定价 O(W) 腿的系数，calibrationDelta 只移动 judgeCalibration 单轴阈值（W-M3 见证），二者都住在 R22-D 已归档的同一休眠对象内部。
2. **计时的归因独立性**：即便计时，任何 µs 都只是 R22-D S1a-4 网格的重标定（同一 slice/freeze/scan 机制换系数）——在零流量对象上扩展剂量网格 = R22-D 明文拒铸的「死代码抛光」（其 §3 表对 paretoFront n=512 幻想态的同款裁决）。故按 R31-A F11b 纪律**故意不计时**。
3. **真实规模潜力**：零流量 ⇒ 任何配置下节省恒为 0 ms/run，与数十~数百 ms 落地线的差距是无穷倍。

**语义见证（W-M1–W-M4，×5 运行全过，故意不计时）**：

- **W-M1 配置验证 fail-closed**：windowSize=0 / 1.5、calibrationDelta=0 / 1.5 / NaN 全部 DomainValidationError（fail-open 家族保持关闭）。
- **W-M2 windowSize 剂量只改判定发火点、不改机制**：同一 24 观测流（16 基线族 + 8 unseen 尾），W=4 宣告 model+taskMix 漂移（尾窗全 unseen 多数），W=16 不宣告（8/16 非多数）。
- **W-M3 calibrationDelta 单轴隔离**：0.3 校准移位在 delta=0.5 下零轴发火、在 delta=0.2 下**恰** judgeCalibration 单轴发火（uncertainty=0.2，其余四轴 false）。
- **W-M4 新钉结构事实：快照合同不含配置**——`snapshot()` 是纯观测历史（24 项普通对象数组），restore 到同配置消费者后续判定逐位同（drifted），restore 到 W=16 消费者按**消费者**配置判定（同一续观测不漂移）；配置住在消费者、历史是唯一状态（与 R30-D W-A「profile 非持久」同型的非持久见证，monitor 版）。

**裁决**：不铸 ID、不起绰号、不加 EXCLUSIONS 行、也不作为新停放门——该格并入 R22-D 属地，重开条件维持 R22-D §5 原文并显式扩展覆盖配置平面：(a) 任一休眠导出获得生产调用方（届时以调用频率 × 单价对照 10 ms 线，windowSize/calibrationDelta 剂量随 R22-D 网格一并重开）；(b) monitor 接入长驻进程（无界 `observations` 升格为内存正确性问题——按**正确性**而非性能重开，windowSize 上界随之成为正确性参数）；(c) 导出面结构变更。

function mulberry32(seed: number): () => number {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) >>> 0;
    let t = a;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
function pick<T>(rng: () => number, items: readonly T[]): T {
  return items[Math.floor(rng() * items.length)] as T;

async function benchAsync(fn: () => Promise<void>, reps: number): Promise<number> {
  await fn();
  const t0 = performance.now();
  for (let i = 0; i < reps; i += 1) await fn();
  return (performance.now() - t0) / reps;
}
/** Time-boxed sync bench, returns ms/call. */
function bench(fn: () => void, minMs = 60, maxReps = 50000): number {
  fn();
  fn();
  let reps = 0;
  const t0 = performance.now();
  let elapsed = 0;
  do {
    fn();
    reps += 1;
    elapsed = performance.now() - t0;
  } while (elapsed < minMs && reps < maxReps);
  return elapsed / reps;
}
