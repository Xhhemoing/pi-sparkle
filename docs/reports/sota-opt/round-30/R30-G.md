## 结论

**无可落地的新更优解，本轮生产代码零改动，切片维持关闭
（MORE_OPTIMA=no）。** 第三十遍为本切片**连续第十九次完全空枚举**
（R12-G…R29-G、本轮），并新增一条前二十九轮从未做过的真实新轴：
**M1 父运行子任务依赖调度格 / M1 parent-run child-scheduling lattice
face（战役首创）**——R29-G 找到切片里的「第二台运行引擎」（M2
`runSupervisorRounds`）之后，本轮清点确认切片里还藏着**第三、第四台
引擎**：`src/run/coordinator.ts` 的 `startRun`（M0 单代理转写循环，
生产 `run` 命令主路径、即锚点 300-append I/O 地板本体）与
`startParentRun`（M1 父运行依赖调度器）。M1 是一台与 flowchart 引擎、
M2 轮循环都不同的**Promise.race 依赖调度机械**：`startReady`
（coordinator.ts:391-413）按 `dependsOn` 出圈就绪子任务（全部依赖
SUCCESS|PARTIAL 才 ready）、对失败依赖（FAILURE/TIMEOUT/CANCELLED）
**静默剔除**（splice 出 remaining，不落任何事件）、主循环对活跃句柄与
子任务 QUESTION 竞速（:430-435）、跟踪门指令消费臂（wait_user /
queue_analysis，:455-464）、终局结算四臂（aborted→CANCELLED；
failures 非空→FAILED；remaining 非空→FAILED "unstarted children"；
否则 COMPLETED，:476-489）。被扫格 = **依赖拓扑**（独立 / 链 / 菱形 /
扇出）× **依赖结局类**（SUCCESS / PARTIAL / FAILURE / TIMEOUT /
CANCELLED 对 startReady 门的作用）× **剔除级联与饿死**（unstarted
children 臂）× **提问竞速臂** × **父中止臂** × **终局结算类**。历史
核对：29 轮报告全文中 `startParentRun` 仅在 R24-H 作过一次路过式
组合参照（H 切片实参物化面，零调度剂量）；R8-G §4 曾按「S1-G-6/7/8
族覆盖完备」把 coordinator.ts 记为无新环——那是**微观循环**裁决
（splice/filter/Set 化），依赖调度格四个自由度没有一个被任何轮当过
被扫变量；既有集成测试（m1/parent-run 两件 + m3 coverage-gate +
cluster 两件）只驱动过父中止臂与提问臂两格。本轮以 13 个真跑格
（真实 `startParentRun` + 六款脚本化 executor + 真实文件态
EventStore/CheckpointStore/EpisodeStore）+ 每次发射计算面微定价
（groundChildTask / formatChildPrompt，二者亦为战役首次定价）把该面
**全维度定价**，冒烟 + 三正式批结构摘要 `72bc37c9c2d092d5…` 12 次
逐位一致（另加 8 次跨进程核验 ×3 迭代全部同值）——三重收口全部
反向，未铸 S30-G-*：

1. **缺省生产剂量为字面零格且比 R29-G 的 M2 更空**：`startParentRun`
   **无任何 CLI 调用方**（rg 全库复核：仅 coordinator.ts 自身 +
   test/integration/{m1,m3,cluster} 五件），且 M1 **连 resume 门都
   没有**（M2 至少还有 `resume --supervised` 半扇门）；缺省内部生成
   流量（`--children`）走 flowchart 引擎编译路径，`--track` 循环在
   track/loop.ts 自持编排（仅 import RunOutcome 类型），M1 调度格
   剂量字面 0。
2. **调度机械全部 ns/µs–低 ms 级**：`startReady` 出圈算术 n≤maxTasks=16
   的 O(n²) splice/indexOf 属 ns–µs（其 Set 化即已排除的 S1-G-6 族，
   不重开）；每子任务机械份额 ~10–12 appends ≈ 0.7–0.8 ms/子
   （66.8–69.3 µs append 地板换算，L1 12.5 vs L12 扇出 10.4
   appends/子）；每次发射计算腿 groundChildTask 1.7–2.1 µs +
   formatChildPrompt 0.31–0.92 µs，全在全局计算顶 0.281–0.294 ms/run
   封顶之内两个数量级；整格墙钟 4–13 ms/run 且每 run 一次（L9/L13 的
   ~31–35 ms 是 25 ms 定时器按构造墙钟）。假设性流量下真实支配成本是
   executor 的秒-分级真跑。距十毫秒改良门槛 1–4 个数量级，全落 µs /
   每 run 噪声拒收族。
3. **矛盾格修复与事件序串行化是行为改变，撞纪律**：CANCELLED 子任务
   落 run COMPLETED、跟踪门抢占 failures 结算臂、剔除/饿死零事件、
   父日志双写者交错——都是结算语义与审计迹的正确性领地，不是可折除
   开销；一切按 proposal-first 纪律仅入档观察，不改产码。

**语义普查事实（非性能洞，随轴入档，proposal-first 不作 Outcome
声称）**：(a) **跟踪门抢占 failures 结算臂**（L3/L4）——带终端
TASK_RESULT 的 FAILURE 子任务先过跟踪门（applyChildThreeLine），门发
`queue_analysis` 指令 → 主循环立即 break → run **RUN_BLOCKED**；
`failures.length>0 → RUN_FAILED("<task>: <summary>")` 臂对**有终端的
失败永不可达**，只有无终端失败（L8）与超时（L9/L13，门因无终端跳过）
才能走到；(b) **CANCELLED×COMPLETED 矛盾格**（L6）——executor 宣告
CANCELLED（非父中止）的子任务不落 failures 过滤器
（只筛 FAILURE|TIMEOUT，coordinator.ts:473-475），单子取消 run 竟
**RUN_COMPLETED**（子日志同时躺着 RUN_CANCEL_REQUESTED——两本日志
互相矛盾）；(c) **静默剔除与饿死**（L3/L7）——依赖失败的子任务被
splice 出 remaining **不落任何事件**；其下游因依赖「从未 finished」
而饿死滞留 remaining；饿死名单只有在 failures 为空时才见于
`RUN_FAILED "unstarted children: …"`（L7），failures 非空时被完全
遮蔽（L3 的 c 无处可查），且名单不写原因也不写被剔除者（L7 只报 c
不报 b）；(d) **PARTIAL 双面性**（L5）——PARTIAL 既放行下游
（ready 判据 SUCCESS|PARTIAL）又不入 failures，链形状与全 SUCCESS
逐项同（15/10 appends），PARTIAL 语义在 M1 面不可辨（与 R29-G M2
折叠臂同型，机制不同：M2 在 toTaskOutcome 折叠，M1 在两处过滤器
双侧漏过）；(e) **父日志追加序非确定**（L4 三运行翻转见证）——
同一 startReady 批发射 >1 子时，主循环的门控追加（TRACKING_ASSESSMENT/
GATE_TRANSITION/RUN_BLOCKED）与下一子经 ConcurrencyGate 释放后的启动
追加（CHILD_RUN_CREATED）是**两条并发写链**，到达序随 I/O 完成时序
翻转（多重集恒同、计数恒同、终态恒同）；对照 flowchart 引擎
S4-G-1 串行 await 硬禁与 M2 严格顺序轮循环，M1 是三台引擎里唯一
事件序不定的；(f) **提问后到达的结果不过门**（L10）——question 胜出
竞速后主循环退出，兄弟子任务在 finally 的 allSettled 排水期跑完，
其 TASK_RESULT 落 CHILD_MESSAGE 但**不再过跟踪门**（无
TRACKING_ASSESSMENT，13/10 appends vs L1 15/10），run 已定格
WAITING_FOR_USER。均不构成计算洞，不铸 ID。

## §2 新轴：M1 父运行子任务依赖调度格（child-scheduling lattice face，战役首创）

### 2.0 为什么这是 R1-G…R29-G 从未拉伸的完备格

历史 G 报告全文核对：`run/coordinator.ts` 只以两个侧面出现过——
(i) R8-G §4 按「S1-G-6/7/8、S2-G-1/2/8 族覆盖完备」记为无新环，那是
**微观循环**（splice/filter Set 化、指针化、Date.parse 缓存）裁决，
不是调度格维度；(ii) R24-H 在 freshness 配对腿把 `startParentRun`
的 tasks 构造形态当组合参照（H 切片实参物化面，零调度剂量）。M0
`startRun` 的五臂转写循环是生产 `run` 命令主体，但它**没有子任务、
没有依赖、没有调度格**——其成本即 §1 锚定的 300-append I/O 地板，
逐臂事件混合扫描属 workload-composition 移植（禁）。**依赖拓扑维
（链/菱形/扇出从未跑）、依赖结局门维（PARTIAL/CANCELLED/TIMEOUT 对
startReady 的三类作用从未跑）、剔除级联与饿死臂（unstarted children
从未跑）、终局结算类维（failures 拼接臂 / unstarted 臂 / 门抢占臂
从未跑）——四个自由度没有一个被任何轮当过被扫变量**。它们恰构成
一条新完备格：**拓扑 × 结局门 × 剔除/饿死 + 提问竞速 + 父中止 +
结算类**。

与近邻轴的正交性（铸名前逐一对照）：**R30-A call-stream ordering /
dispatch-history face** 扫的是**同一多重集**的门调用以什么**排列次序**

/** Dispatches one scripted behaviour per taskId (keys are short ids, e.g. "a" -> tsk_a). */
class ScriptedExecutor implements AgentExecutor {
  private readonly scripts: Map<string, Script>;
  constructor(scripts: ReadonlyMap<string, Script>) {
    this.scripts = new Map([...scripts.entries()].map(([short, script]) => [String(createTaskId(() => short)), script]));
  }
  async *execute(request: AgentExecutionRequest, signal: AbortSignal): AsyncIterable<ExecutionEvent> {
    const script = this.scripts.get(String(request.taskId));
    if (script === undefined) throw new Error(`no script for task ${request.taskId}`);
    switch (script.kind) {
      case "terminal":
        yield { type: "MESSAGE", message: terminalMessage(request, script.outcome, script.verification) };
        yield { type: "EXECUTION_FINISHED", outcome: "SUCCESS" };
        return;
      case "claim-success":
        yield { type: "EXECUTION_FINISHED", outcome: "SUCCESS" };
        return;
      case "exec-cancelled":
        yield { type: "EXECUTION_FINISHED", outcome: "CANCELLED" };
        return;
      case "hang":
        await new Promise<void>((resolve) => {
          if (signal.aborted) return resolve();
          signal.addEventListener("abort", () => resolve(), { once: true });
        });
        return;
      case "question":
        yield {
          type: "MESSAGE",
          message: validateAgentMessage({
            protocolVersion: 1,
            id: createMessageId(UUID),
            occurredAt: T0,
            runId: request.runId,
            taskId: request.taskId,
            from: request.agentInstanceId,
            to: SUPERVISOR,
            type: "QUESTION",
            question: "Proceed with the risky refactor?",
            options: ["Yes", "No"]
          })
        };
        return;
      case "sticky": {
        script.onStart?.();
        yield { type: "TEXT_DELTA", text: "working" };
        await new Promise<void>((resolve) => setTimeout(resolve, script.holdMs));
        yield { type: "EXECUTION_FINISHED", outcome: signal.aborted ? "CANCELLED" : "SUCCESS" };
        return;
      }
    }
  }
}

function typeCounts(types: readonly string[]): string {
  const m = new Map<string, number>();
  for (const t of types) m.set(t, (m.get(t) ?? 0) + 1);
  return [...m.entries()]
    .sort(([a], [b]) => (a < b ? -1 : 1))
    .map(([t, n]) => `${t}:${n}`)
    .join(",");
}

async function runCell(input: {
  name: string;
  scripts: ReadonlyMap<string, Script>;
  children: ChildTaskInput[];
  stateRoot: string;
  projectRoot: string;
  cells: Cell[];
  idOffset: number;
  orderInsensitive?: boolean;
  cancelAfterStart?: () => Promise<void> | void;
  startedPromise?: Promise<void>;
}): Promise<void> {
  counts = zero();
  appendLog = [];
  const executor = new ScriptedExecutor(input.scripts);
  const start = performance.now();
  const running = startParentRun(
    {
      stateRoot: input.stateRoot,
      executor,
      registry,
      now: () => T0,
      generateId: sequenceGenerator(input.idOffset)
    },
    { projectRoot: input.projectRoot, objective: `cell ${input.name}`, children: input.children, limits: limits() }
  );
  if (input.cancelAfterStart !== undefined) {
    if (input.startedPromise !== undefined) await input.startedPromise;
    await input.cancelAfterStart();
    running.cancel();
  }
  const outcome = await running.done;
  const ms = performance.now() - start;

  const parentEvents = appendLog.filter((entry) => entry.runId === running.runId);
  const childAppends = appendLog.length - parentEvents.length;
  const failed = outcome.events.find((e) => e.type === "RUN_FAILED");
  const reason = failed !== undefined ? String((failed.payload as { reason?: string }).reason ?? "") : "";
  const childMsgOutcomes: string[] = [];
  for (const e of outcome.events) {
    if (e.type !== "CHILD_MESSAGE") continue;
    const msg = (e.payload as { message?: { type?: string; outcome?: string; taskId?: string } }).message;
    if (msg?.type === "TASK_RESULT") childMsgOutcomes.push(`${msg.taskId}=${msg.outcome}`);
  }
  input.cells.push({
    name: input.name,
    status: outcome.status,
    failureReason: reason,
    parentTypeSeq: input.orderInsensitive === true ? "(counts-only)" : parentEvents.map((e) => e.type).join(">"),
    parentTypeCounts: typeCounts(parentEvents.map((e) => e.type)),
    childOutcomes: childMsgOutcomes.join(","),
    launched: parentEvents.filter((e) => e.type === "CHILD_RUN_CREATED").length,
    ops: { ...counts },
    parentAppends: parentEvents.length,
    childAppends,
    orderInsensitive: input.orderInsensitive === true,
    ms
  });
}
