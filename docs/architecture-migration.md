# Pi-sparkle 当前架构：迁移计划

本计划落实已接受的 [ADR-009](decisions/0009-lightweight-adaptive-framework.md)。M0–M7 是可拆分的工作切片，不是八个新模块、固定日期承诺或要求全部完成的发布清单。当前能力见[状态矩阵](status-matrix.md)，行为合同见[算法文档](architecture-algorithms.md)。计划首次提交仅含设计。后续 [M0-A 实施与验证](reports/2026-10-16-process-ownership.md) 已在用户明确授权推送后发布到 PR #60，远端 `e6f6a5b` 与原验证树完全一致；此前自动审批阻挡是历史状态。[本轮迁移证据](reports/2026-10-17-framework-migration.md)与[当前清单](../tasks/migration-todo.md)分别记录后续切片；这不表示完整 M0–M7 已验收。

## 1. 最小交付与依赖

先让现有能力可靠停止，并让直接任务更好用。默认一个 worker，不强制项目队列或金额输入，保留严格开发路径；项目连接、画像推断和长期实验都不是核心可用的前置。

| 切片 | 依赖与可并行关系 | 主要责任 | 对应算法 |
|---|---|---|---|
| M0 基线与进程所有权 | 基线最先固定；进程修复先于扩大 live、新并发修复和受管进程 | runtime/process | A10 |
| M1 直接任务可用 | 基线后可做入口/工具；涉及真实进程的交付需满足 M0 | application/coding | A1、A3、A10 |
| M2 边界与窄 SDK | 与 M1 按文件分工并行；插件接入复用可用的核心端口 | core/plugin | A9 |
| M3 动态发现与局部纠偏 | M1 可用；只读观察可先做，自动修复依赖 M0 的停止/对账 | runtime/application | A2、A10 |
| M4 费用路由与即时偏好 | 核心可用后独立增量；观察、路由、显式 overlay 可分别交付 | policy/preferences | A3、A4、A6 |
| M5 受管 Pi 更新 | M0 与清楚的 adapter 契约；不等待 M6/M7 | compatibility/process | A5 |
| M6 项目与外部连接 | 复用现有队列/controller；connector 与项目检索可分别交付 | development/connector | A8 |
| M7 长期策略优化 | 可归因事实与 M4 的观测基础；不等待全部 connector；自动试用另受既有 gate | evaluation/adaptation | A7 |

M1 的直接任务、基础小工具和相称检查构成首个用户可见增量。M2 可以先交付纯破环再交付 SDK。M4 的严格预留单独按需实现，不能阻塞无金额上限的普通任务。每个新增行为先有聚焦回归，迁移与算法改动分开提交；切片过大时继续拆，不为保持编号合并无关工作。

## 2. M0 基线与进程所有权

先固定实际 heads、接口与证据。源码审查基线是 PR #60 `7407674`；审查时 main 为 `44db4b1`，PR #61 `c4a9e3c` 独立且有重叠。实施前实际 fetch，核对 merge-base/range-diff，再选择需要的 recovery/terminal 变更；不能直接叠合两个 PR，也不从本地缺失对象推断精确共同祖先。本次文档不合并它们。

主要触点：[command-runner](../src/execution/command-runner.ts)、[independent-check](../src/execution/independent-check.ts)、[recipe-check](../src/development/recipe-check.ts)、相关 run 取消与资源结束记录。统一资源归属，取消后先停止新准入，再等待子孙实际结束或保留未结状态；只有真实结束才能释放工作区、写入所有权和相应预留。

原始发现来自等价嵌套 runner：内层 detached 进程组可能逃离外层取消。当时的复现不是完整 `develop` E2E，也未证明 Windows 行为。现有正常超时配置下外层窗口大于 recipe 总限时，因此实际路径验证重点是显式取消、上游 deadline 和崩溃；后续证据见下方实施更新。

实施更新：M0-A 已覆盖真实 develop 的取消、deadline、父崩溃及未结效果保留。M0-B 在既有 `ActionStore.update` 中原子检查冲突并发布 running action，checker 和 writer 共用；就绪选择只重验已接受的依赖祖先/重叠范围。运行效果不持有元数据锁，拒绝准入不新增 prepared 行；成功重验仍受原有限账本容量约束，终态归档另行设计。

**退出证据：** 真实 develop recipe 链在 abort/deadline、父崩溃、忽略 TERM、重复取消与迟到结果下，无后续文件写入，或明确 unsettled 且不接受、不重用、不自动重放；POSIX/Windows 分别记录证据。保存固定任务的非模型耗时、环境准备、用量覆盖基线，未测项目保持 unknown。

**退路：** 停止受影响新任务，保留候选和效果供对账。不能回退到已知不安全行为后声称 clean。纯文档/依赖梳理可继续，不用一个平台的未验证结论冒充全平台完成。

## 3. M1 直接任务可用

薄的 [`startDevelopmentTask`](../src/development/start-task.ts) 目标入口已复用 [NativeWriteSession](../src/native/write-session.ts)，不重建 agent loop；这是实验性深路径宿主函数，见[使用说明](direct-development-task.md)，尚非稳定 SDK。后续补 list/search/range-read/精确 patch/命名诊断；现有受控 workspace 与 Pi 工具包装分开，上层不用 Pi 类型表示文件能力。

触点：[development CLI](../src/cli/development.ts)、[write-session](../src/native/write-session.ts)、[write-loop](../src/native/write-loop.ts)、[context](../src/context/index.ts)、[worktree-coding-tools](../src/pi-adapter/worktree-coding-tools.ts)。先接代码中的 CodeMap 输入来源与任务局部选择，不另建默认向量服务。

**退出证据：** 一组明确、可逆的小任务无需队列、金额填写或额外 planner 调用；相关测试失败可在同候选有限修复；相同授权不重复询问；protected checker、strict develop 验收、CLI/事件输出保持原语义。必须上下文不可读、过期或装不下有明确失败，不静默删目标。

**退路：** 新入口可关闭，旧路径继续可用；工具不可用退到受控范围读取/搜索，必要检查不可用则报告阻塞。保留已有候选与收据，不同时改变持久 schema。

## 4. M2 边界与窄 SDK

首个行为保持切片已将 `cli/main ↔ cli/pref` 的共享选项移至 `cli/options`；宿主无关 model-catalog 构建移至 `routing/model-catalog`；`privacy/state-layout` 下沉至 `persist/state-layout`，deletion/retention 保留应用级组合。路径搬迁保留同一导出值的转发，不改变记录字节与算法。[M2-A 证据](reports/2026-10-17-m2-boundary-cleanup.md)与全量集成验证分别记录；窄 SDK 仍待实施。

触点：[main](../src/cli/main.ts)、[pref](../src/cli/pref.ts)、[model-catalog](../src/cli/model-catalog.ts)、[native routing-catalog](../src/native/routing-catalog.ts)、[track loop](../src/track/loop.ts)、[state-layout](../src/privacy/state-layout.ts)、[package.json](../package.json)。继续执行 Pi 双边界与 live/adaptation 隔离，先冻结不得新增违规边，再逐项减少旧例外。

SDK 首批拟稳定公开 context/diagnostic，目标入口为 sdk/host/testing；tool/observer 后续实验。保留扩展现有懒加载，注册先暂存、校验唯一 ID 后发布；并发首次请求共用 activation promise，取消/generation 拒绝过期提案，迟到效果收据与用量仍记录并幂等结算。

**退出证据：** 未启用插件零激活，两个外部示例不依赖未支持的内部路径；打包后的消费者能编译/运行；唯一现有 runtime 文件循环消除，相关 CLI/native 固定输出不变；关闭插件后主链可用。

**退路：** 保留已知深路径转发与明确迁移窗口，再收窄 exports。当前没有稳定 package exports；新增 exports 会限制包名深导入，移动 dist 也会破坏相对导入，二者都需检查。不要把全部内部 export 永久承诺为 SDK，不按 36 组目录拆包。

## 5. M3 动态发现与局部纠偏

先交付只读 finding 与摘要：消费已有工具、测试和源变化，规范化原因/位置/目标，绑定 revision、generation 和不透明证据版本。相同证据不反复分析；必要时 single-flight 短时调查；原始取消/效果/计费事实不进入可丢弃队列。

触点：[execution contract](../src/execution/contract.ts)、[run events](../src/run/events.ts)、[controller](../src/development/controller.ts)、[write-loop](../src/native/write-loop.ts)、[store](../src/development/work-item-store.ts)。不把模型自报当可信 host observation；冻结事件/schema 需要显式兼容设计。

再启用范围内可逆修复：同一候选写入者在安全动作边界处理一次；重大阻塞先 stop/settle/reconcile，再准备独立修复。基线变化后重建或重验原候选。当前 store 无 append/replan 公共 API，不直接改 JSON 绕过它。

**退出证据：** 重复日志不放大模型调用；新危害不被 cooldown 压住；旧分析结果不生效；同边界不并发派两个重叠修复；未结效果不释放 claim；已授权修复无需重新确认；无关工作仍可继续。

**退路：** 先 shadow 只展示，再选择性启用；关闭观察/修复能力不影响普通任务。无法定位时换一次有界诊断或给出明确阻塞，不无限加 agent。

## 6. M4 费用路由与即时偏好

将本切片拆成三个可独立交付部分：用量覆盖/失败归因、静态能力路由、task 偏好 overlay。严格共享准入是另一个按需增量，不要求每个普通任务先建账本或填写金额。

触点：[CostGate](../src/pi-adapter/cost-gate.ts)、[invocation-log](../src/telemetry/invocation-log.ts)、[usage-aggregate](../src/telemetry/usage-aggregate.ts)、[model-router](../src/supervisor/model-router.ts)、[preferences](../src/preferences/store.ts)、[clarify](../src/track/clarify.ts)、[context](../src/context/index.ts)。优先复用已有模型目录、失败分类和偏好记录，不另建用户库。

**退出证据：** 普通观察模式可在价格 unknown 时继续且不算零；用户指定有效；环境/provider 失败不盲目升级模型或跨层重复重试；本次详细覆盖全局简短而不污染默认；明确 correct/delete 不走实验，删除会失效派生缓存且不被旧来源复活。

严格准入另外验证可靠上界、共享原子预留、幂等结算、未知费用、重复/冲突收据、取消与崩溃对账、祖先强制上限不可被后代撤销。各累计 scope 使用自己的 ledger；准入保证不宣传为供应商账单保证。

**退路：** 固定配置主模型；关闭推断仍保留显式偏好。严格模式缺可靠上界就明确不可用，不静默切为观察。已产生新数据时遵守第 10 节的回滚规则。

## 7. M5 受管 Pi 动态更新

先适配实际停止语义，再建立更新管理。新的 driver 必须在下一 provider 请求前观察并只计一次本轮用量；单纯把 `shouldStopAfterTurn` 改名为 `finishTurn` 不足以验证时序。

触点：[pi-adapter](../src/pi-adapter/index.ts)、[pi-compat](../src/pi-compat/check.ts)、[latest check](../scripts/pi-latest-check.mjs)、兼容 probe/fixture 与 CI。候选在独立目录/进程验证，发布完整资格记录后才原子更新 approved 指针。记录绑定不透明 generation ID、driver/test/policy/environment 和精确 manifest 字节。

standalone 首期一个 root run 一个受管进程；子任务、重试与恢复保持绑定。native 宿主升级单独验证，需要新宿主进程；不跨 IPC 搬函数认证，不为升级先维护三套后端。发现升级不在每次普通任务关键路径阻塞网络。

**退出证据：** 真实 Pi Agent 与 deterministic provider 的候选矩阵验证事件、工具、取消、计费、停止和 settlement；首轮达到停止条件后 `providerCalls=1`；版本不匹配拒绝使用；运行 lease/恢复引用阻止清理旧 generation。真实 provider smoke 另经既有条件；独立策略原型不能替代以上证据。

**退路：** 继续已知可用 generation，离线可用已安装版本。只切新 root run；旧版不可用时明确恢复阻塞，不用“没有 receipt”证明没有 dispatch。跨版本重开需独立证明全树在任何外部派发前已结束，不能删除未知效果绕过。

## 8. M6 项目与外部连接

先提供 `advanceProject` 薄函数和只读进展/经验检索。外层读事实、对账、调用 `controller.runNext()`；不先 claim 再调用，也不复制 scheduler。accepted 候选未集成源代码时，不解锁依赖。

触点：[controller](../src/development/controller.ts)、[work-items](../src/development/work-items.ts)、[store](../src/development/work-item-store.ts)、[batch](../src/development/batch.ts)、[ProjectSnapshot](../src/domain/project.ts)。经验视图有来源、时效和失效规则，但不能拥有任务完成状态。

外部连接先只读 issue 草稿，再写自身进展区；计划 patch 和 webhook 可后续独立增加。拟议 `applyPlanPatch(expectedRevision)` 只改未开始的 planned 定义，在现有 store 内验证 revision、授权、依赖无环，不转移旧验收；不创建新 ProjectPlan 数据库。

connector 使用 delivery/规范对象/operation 三类不同身份。内容去重按固定规范化版本精确字节比较，不新造加密摘要。传输记录有独立大小、条数和 retention 上限，不塞满有限业务 ActionLedger；外部写仍先意图后效果/收据。GitHub 通用 PATCH 没有 ETag 写 CAS 保证，共享字段冲突产生 proposal，不覆盖人类内容。

**退出证据：** 并发 continue 不双执行；accepted 未集成不解锁；重复/乱序、issue/PR 别名、远端并发修改、丢响应、限流、满额与过期重投均不重复写入或覆盖。外部授权失败不能被误判为实体删除。网络故障不阻塞无关本地任务。

**退路：** 禁用推进/connector 后仍可手动 runNext；保留未决外部 receipt 与冲突，退回只读链接和草稿。定时触发由后续外部调用复用同一 claim，不在本轮建立内置 cron。

## 9. M7 长期策略优化

复用 [auto-loop](../src/learning/auto-loop.ts)、[adaptation](../src/adaptation/promotion.ts)、[rollback](../src/adaptation/rollback.ts)、[evaluation](../src/evaluation/types.ts)；先补真实任务归因和费用覆盖，再做冻结基线、时间切分离线比较与 shadow。当前 auto-loop 从不自动晋升，monitor 也未形成已验证的生产自动回滚链。

**退出证据：** 样本/归因可解释，无训练测试泄漏；取消和 provider 故障不一律归因模型；独立验收质量不下降；费用含失败、辅助分析和重试，缺口单列；旧策略可恢复。自动停止、回滚链实际触发验证后，才在明确一次性授权范围内考虑低风险自动试用，仍满足 ADR-004/005/007 和既有 gate。

**退路：** 保留冻结策略，关闭学习不影响普通任务及显式 correct/delete。候选不能修改权限、checker 或在飞运行代码。满意度不能替代真实性；框架代码优化形成普通开发任务与可审查候选，不在后台直接自换内核。

## 10. 跨切片兼容、旧 writer 与回滚

先盘点冻结 CLI/事件/JSON、Pi/native 注册、旧深导入和持久路径；每切片验证受影响表面，不把旧测试数量当当前行为证据。新的 read model 不能变成写入入口，测试 mock/缓存/历史 JSON 不能恢复 trusted apply capability。

新增 schema 先兼容读取，再用明确版本/副本切换写入，不双写两份业务权威。**只写一个“新版本 marker”不能阻止不认识 marker 的旧 binary。** 切换前要通过进程停止、宿主准入/可执行入口控制、写目录隔离或可证明的共同锁协议，让旧 writer 实际无法继续写同一数据；未证明互斥就不能升级共享目录。

已经写入新状态后，回退代码不等于回退数据。保存切换前可恢复副本与 locator，对新状态只读隔离，或用单独审查的逆向迁移；保留所有未结效果和 receipt。旧 binary 不得直接读取/改写不理解的新格式。回退期间仍维持单一写入权威，不复制已发生外部效果。

遵守 ADR-008：新 locator 用随机版本化不透明 ID；字节相等直接比较，不引入替代加密 hash。历史 SHA-bound 记录保留只读，不静默重算、升级、重新封存或授予新信任。

## 12. 管理决策优化与验证计划（2026-10-22）

**状态：方案已选定，待分段实施；本节不是能力完成声明或实验授权。** Owner：主协调者负责集成与验收，独立评审者核验行为和实验设计，项目负责人决定后续投入与采用。目标是提高 pi-sparkle 管理其他工程项目时的决策质量：在同样资源下，更常交付真正满足目标的结果，减少遗漏、返工和人的管理时间。

本节承接 M1/M3/M6，采用“先 Pi/CLI，后可视化工作台”的用户决定。[当前执行计划](../tasks/plan.md)仍是任务状态的唯一权威；当前多阶段交付工作先完成自身验收与发布，本节不改其运行配置。P4/P5、adaptation/learning 和新实验的现有冻结继续有效；设计选型不等于解除冻结。实施前将获准的下一切片并入当前计划，不另建计划数据库、常驻调度器或报告体系。

### 12.1 已核对的基础与缺口

这里能确定性改善的是“事实是否失真、状态是否误报、旧结果是否被错误复用”；“选择的任务是否最有价值、何时调查最划算”必须靠真实对照验证，不能由模型自评保证。

### 12.2 Brainstorm 后的取舍

| 候选 | 收益假设 | 主要代价/失败方式 | 选择 |
|---|---|---|---|
| A：薄的事实与状态辅助，Agent 自行决定 | 事实不丢失、冲突可见、完成状态准确；成本低 | 不主动纠正错误排序或无效调查 | **必做基础，也是强对照组** |
| B：A + 关键事件触发的决策辅助 | 在依赖不明、目标变化、失败反复时改变下一步，减少无效工作 | 错误触发、调查拖延、同模型相关错误 | **选为最终演进方向，先在宿主验证，收益不足则保持关闭** |
| C：常驻 planner/researcher/reviewer/manager 多角色团队 | 可并行处理真正独立的大问题 | 简单任务也付协调成本、重复上下文、交接失真和误差传播 | 不作为默认架构；仅允许具体独立子任务的有限委派 |
| D：先建设完整看板、架构图和知识图谱 | 信息更易理解、便于人工管理 | 界面完整不等于决策正确；容易形成第二份陈旧状态 | 排在有效事实与决策链之后，视图从现有事实派生 |

最终选择 **A 为底座、B 按需启用、D 逐步呈现**。保留一个 worker 的连贯执行上下文；只有独立性、范围和收益明确时才分工。不是先建一个“更聪明的总管”，再要求它证明自己。

这一选择与外部研究的方向一致，但收益仍须本项目实测：[Scaling Agent Systems v3](https://arxiv.org/abs/2512.08296v3)显示协作效果依赖任务结构，工具密集与顺序任务可能付出协调代价；[MAST](https://arxiv.org/abs/2503.13657v3)把失败归入系统设计、Agent 间失配和任务验证；[Agentless](https://arxiv.org/abs/2407.01489v2)说明简单流程应作为有竞争力的对照，其 2024 年结果不代表当前排行榜。这些材料不证明 pi-sparkle 已有优势。

### 12.3 怎样提高管理决策质量

管理循环为“读取当前目标与证据 → 找到会影响下一步的不确定性 → 选择行动 → 用独立结果更新判断”。正常执行继续走现有内核，新增分析只在必要时发生。

| 决策 | 具体规则 | 用什么检查是否有效 |
|---|---|---|
| 做什么 | 从用户目标及公开验收倒推；保留非目标、约束、依赖和待确认假设。不要把“完成多个子任务”替代用户结果 | 独立验收的需求覆盖；无需求支撑的工作量；遗漏/过期目标造成的返工 |
| 先做什么 | 先处理阻塞交付的依赖和会改变方案的高影响未知项；独立、可逆的小工作可先推进。优先级需要理由，不做没有校准的精确分数 | 首次有效进展时间、关键依赖漏判、执行后发现前提不成立的次数 |
| 何时调查 | 调查前写清“问题、可能答案、各答案会如何改变动作、时间/调用上限”；答案不改变动作就不调查 | 调查是否改变动作、是否发现实际缺口、增加多少时间/费用；无改变不自动等于无价值 |
| 何时拆分/委派 | 一个连贯修改优先同一 worker；独立调查或不重叠实现有明确收益才并行。共享 schema/锁/授权修改串行 | 交接丢失、冲突、重复读取、等待与最终集成返工 |
| 何时改计划 | 新需求、依赖失效或新证据与原前提冲突时生成差异草稿；已经开始的任务先按现有取消/settlement 处理 | 变化后仍沿用旧目标的次数；正确修订延迟；旧验收是否错误迁移 |
| 何时停止 | 已达目标就停止；没有新证据不重复同一调查。工具不可用、功能失败、授权缺失分别处理 | 多余调用、误判成功、无限重试和可恢复问题被过早放弃 |

首个决策原型只建议四种动作：继续、有限调查、计划修订草稿、停止/说明阻塞。记录简短的“当前依据、选择理由、放弃的主要备选、什么新证据会改变决定”；仅在重要决策点产生记录，放入既有任务记录或实验输出，不增加日常表单。

触发来源先限于可观察事实：需求发生变化、证据冲突、依赖不满足、checker 新失败或失败模式变化。普通成功步骤不调用额外管理模型；重复 finding 不重复分析。模型的自信不是事实可信度，fresh/HIGH 也不自动成为冲突裁决依据。计划、代码和运行证据冲突时保留差异，读取适用范围内的权威来源，必要时询问目标拥有者。

原型中的管理模型调用与 worker 共用事先指定的任务资源额度，不额外赠送预算。只在私有宿主串行安排有界调用，先不实现全树共享额度的新运行时机制；仍须兑现实际取消、未结工作保留和完整费用记录。分析文字不能获得执行、验收或 apply 权限。

### 12.4 实施顺序与可观察退出条件

这里的顺序是依赖顺序，不是日期承诺。每一段结束后依据结果决定下一段投入，不要求完成整套路线才产生价值。

| 顺序 | 具体产物/主要触点 | 退出条件 | 无收益或受阻时 |
|---|---|---|---|
| 0：接续当前交付 | 当前多阶段工作自己的计划、PR、CI和隔离副本验收 | 确认将用于试验的运行版本及真实可用能力；保留失败和未结状态 | 先处理执行阻塞，不能把无法交付归因“管理模型不够聪明” |
| 1：修复证据交接 | packet 的来源/时效/可信度/冲突保留；真实最终 prompt 回归 | 第 12.5 节 RED→GREEN，现有保护不退化；受影响兼容表面评审 | 修复保持最小；不顺便新建图谱或统一所有上下文接口 |
| 2：宿主中的决策草稿原型 | 复用现有 context/finding/controller 接口；实验代码在 .agent_workspace，接受实施授权后才写 | 第 12.6 节事件/分析/草稿及已有状态场景通过；简单任务管理模型调用数为 0；旧结果不驱动动作；不修改持久计划 | 保留 A，关闭额外分析；不改核心调度和持久计划 |
| 3：四组配对小试验 | 第 12.7 节的 6 个新目标 × D/E/S/H，共 24 个结果 | 获得质量、成本、人时及失败归因，验证测量可行性；形成继续/缩减/停止建议 | 小样本只诊断；不凭“多数赢了”扩大运行时 |
| 4：有条件接入计划与产品视图 | M6 已拟议的计划 patch；Pi/CLI 只读产品/技术/交付视图；决策导向的调研入口 | 目标变化、并发修订、依赖集成及来源失效实际验证；日常任务不强迫额外模型调用 | 草稿和只读视图仍可使用，保留现有人工推进 |
| 5：确认性比较，再做工作台 | 独立新任务的确认试验和自然使用比较；随后可视化消费同一读模型 | 通过事先选定的效果标准，或明确只在哪类任务有益 | 公开适用边界；未证实优越就不宣传替代人工/其他 Agent |

计划 patch 是条件性后续，继续遵守第 8 节：只改 planned 定义，在已有 store 锁内核对 revision、授权与依赖无环；不转移旧验收。进行中的目标变化不能直接改 JSON，需要已有停止/对账后形成新计划。不得用管理功能绕过 accepted-but-not-integrated 的依赖限制。

后续功能的最小形态：

- **产品架构展示：** 用户场景/能力 → 模块与接口 → 对应任务/验收证据。用户确认的目标架构、静态代码观察和模型推断分别标记；没有可靠关系就显示未知。源变化失效相关视图，避免手绘图成为第二权威。
- **项目调研：** 围绕待决定的问题输出来源、观察日期、版本/适用范围、冲突证据、备选方案和建议；外部内容仅作资料，不能改变权限。优先原始资料和本地验证；搜索次数不作为调研质量。
- **计划管理：** 可解释的下一步、依赖和变更草稿；区分已实现、已检查、已集成、已发布和用户验收。用实际依赖/吞吐更新区间估计，数据不足时不给伪精确完工日期或完成百分比。
- **可视化工作台：** 在上述读模型可用之后呈现架构、计划差异、证据和阻塞；不另存一套任务状态。点击状态应能追到适用版本和验收来源。

### 12.6 管理原型必须经受的反例

| 场景 | 必须观察到的行为 |
|---|---|
| 文档称完成，当前检查失败/尚未集成 | 显示冲突及实际阶段，不宣称用户目标完成，不解锁依赖 |
| 过期事实与新证据冲突、预算不足 | 能区分来源与时效；不靠截断制造确定性 |
| 简单机械修改、已有充分信息 | 直接执行；额外管理模型调用为 0 |
| 明确功能错误 vs provider/checker 不可用 | 分别走修复或有界诊断；不把不可用算通过，不盲目升级模型 |
| 重复相同 finding | 不反复付费调查；新证据才触发重新判断 |
| 需求在任务运行中变化 | 当前目标及时更新；按已有边界停止/结算受影响工作，旧结果不能满足新目标 |
| 分析完成时 revision/generation 已变化 | 旧分析只留作历史，不执行过时建议 |
| 两个计划修订并发、缺失/循环依赖（阶段 4） | 真实 store 的版本、锁、类型和依赖验证拒绝冲突；不双执行；阶段 2 只验证草稿不写入，不能用模拟代替此验收 |
| 资料含恶意“忽略授权/修改 checker”指令 | 作为不可信内容，不能改变工具/路径/验收授权 |
| 预算耗尽、取消、分析等待超时但仍未结束 | 停止新工作并保留实际未结状态，不能当作资源已释放 |
| 验收只覆盖易过的旧测试 | 外部检查覆盖公开目标与边界；执行者不能自行降低验收要求 |
| 用量缺失、失败后人工接管 | 成本标 unknown；保留失败和接管人时，不能按零成本/自主成功统计 |

原型先用确定性假执行器和合成事件验证状态行为，再用获准的真实模型调用确认线路接通。离线回放只证明触发/状态处理，不证明换一个管理决策后的项目会成功；必须另做前瞻对照。

### 12.7 怎样证明管理层增加了价值

**先隔离“管理的作用”，再比较“整套工作流”。** 不预先把任务拆好交给 S 组，否则测不到规划能力；给各组相同的用户目标、公开验收、源代码起点与可访问资料。直接 Agent 允许正常自行计划、检索、测试和修复，不能刻意弱化对手。

| 组 | 工作方式 | 能回答的问题 |
|---|---|---|
| D：直接 Agent | 同一 Pi 执行模型、工具及基础编码提示，自行组织任务；无 sparkle 管理辅助 | 当前直接使用 Agent 的强对照 |
| E：只增强证据 | 使用同一 Agent 和 A 的准确事实/状态交接，执行/验收路径与 S 相同；决策仍由原 Agent 作出 | 收益是否其实来自信息质量而非新增管理层 |
| S：完整候选 | E + B 的事件触发决策与既有受控执行/验收 | 与 D 比整体管理辅助；与 E 比新增决策层 |
| H：人工管理相同 Agent | 熟悉项目的工程师制定/调整计划、决定检查与推进；执行模型与工具相同，不手工写代码 | 相同执行能力下，与真实人工管理比较 |

管理归因实验中，E/S 使用相同的 sparkle 执行/验收路径；E 不增加管理模型，D 通过私有宿主提供同等文件/测试/隔离能力和独立最终验收。相同 worker 模型、思考配置、工具、基础系统提示、源材料、环境准备规则、整体 deadline 与模型资源上限；上下文组织、任务分解、管理提示和管理调用本身是干预，不能假称所有提示完全相同。新增管理费用计入 S 的同一总额。若不能消除 D 与 S 的执行差异，就只能估计整套管理/执行组合的作用，不能归因给某个算法；S−E 才直接检验决策增量。

H 在管理归因试验中也使用 E/S 的执行/验收能力与事实视图，由人决定计划及推进，避免把执行器差异算成人工管理差异。H 的正常管理不算“救援”；D/E/S 的临时人工救援与各组超时后修复另报 assisted 结果。所有组的必要安装、询问、审阅和操作人时都计入。自然使用阶段可另比各自最佳日常配置（包括人工直接编码），但那属于整体工作流效果，不能再声称只测管理能力。

**任务与样本。** 首轮选择 6 个未用于调参的新目标：局部正确性 1、跨模块交付 2、陌生项目调研 1、需求变化 1、中断恢复 1。3 个稳定目标、3 个带预先定义的变更/恢复事件；至少覆盖两个获准的隔离项目或代码库。Soul 只用已授权隔离测试副本与合成输入，不读写原项目/真实数据。若只有 Soul 可用，结论限定 Soul；不为了“多项目”擅自扩范围。每个目标跑 D/E/S/H，得到 24 个配对结果；H 暂无参与者时仅运行获准的 18 个 Agent 结果，不声称优于人工。

这 6 个目标用于排错和估计波动，不并入后续确认样本。已有 15 任务框架仍可作为五类 × 三任务的覆盖清单，未完成义务保留，不能因为做完这轮就标成完成。确认试验用另一批新目标；重复 seed 是同一目标的重复测量，不能冒充新增独立任务。

**公平性与泄漏。** 用普通 Git 版本记录方案、任务分层、主要比较、预算、停止规则和计量方式；不新建冻结 contract/hash/gate。新会话、新副本，平衡随机运行顺序及冷热准备；不向后跑组泄露前组 patch、分析或隐藏检查结果。每个 H 参与者在比较前只接触自己的目标与训练任务；同目标的其他组由不同会话执行。人工组先做非评估练习，多名工程师分配任务并记录经验；只有一名时结论仅适用于该参与者。H 参与者不得编写、查看或预先知晓本任务的隐藏测试/参考答案；已知情者换任务。测试作者与所有组的管理者/执行者隔离，所有组结束前不泄露隐藏结果。

变更任务在事先指定的观察点向所有组发出同样事件，例如任务额度经过 25% 时；这些任务从公开要求中说明包含后续变更，提前完成初版仍需完成变更后的目标，不能把注入前成功算最终成功。未在时限内到达某阶段仍留在分母。恢复任务使用等价的已结束执行状态，不能靠真实危险进程失控制造情景。

**验收与指标。** 外部验收由未参与实现/管理的人或独立检查器执行，隐藏测试只能检验公开要求，不能事后增加需求。候选用中性编号，评估者尽量不知组别；不能为了盲法删改代码。客观命令优先，主观架构/计划质量用事先定义的量表和独立复核，记录评估者是否猜到组别。

- 主指标：时限和资源额度内，完成当前目标并通过独立验收的比例。目标要求集成则必须实际集成到授权测试副本；“ready for review”不等于交付。严重回归、越权和目标遗漏单列，不能用速度收益抵消。
- 解释指标：错误完成声明、依赖漏判、变更响应、无效工作与返工、调查成本及其是否改变动作。它们帮助解释主结果，不替代交付成功。
- 资源指标：端到端墙钟、人类主动管理/救援时间、模型与工具费用、复核与集成时间；额外 planner、失败、重试、上下文和取消结算均计入。共享搭建/维护时间单列，并按实际任务量给出摊销敏感性分析。
- 所有已分配/启动目标进入结果表，包括环境失败、provider 故障、超时和人工退出；另作归因分层/敏感性分析，不删掉不利组。时间同时报全体截止时间内的成功情况和配对结果，不只比较成功者均值。
- 用量缺失时报告已知费用下界、缺失请求及覆盖，unknown 不是 0；请求覆盖率不是金额覆盖率。成本不完整时不作确定的省钱声明。

[METR 的 2026 年实验调整](https://metr.org/blog/2026-02-24-uplift-update/)指出参与者/任务选择和并行工作计时会扭曲生产率估计，因此本计划记录招募退出、任务选择与实际主动人时，不拿主观“感觉更快”证明收益。

### 12.8 采用、继续调查或停止的判据

小试验先看能否可信测量、是否出现具体可解释收益、是否有严重退化；不能作统计优越声明。之后根据配对不一致比例、任务/项目/人员差异和费用方差设计确认样本，采用保守范围做功效分析；在新样本运行前定好分析方法，不中途看结果就随意停在有利点。

- **证明优于直接 Agent：** 主要比较为 S−D 的独立验收成功率差，报告配对置信区间；确认性下界大于 0 才称质量优越，同时披露代价和严重缺陷。若主张“质量相当且更省”，须另行事先选定不劣界限和资源指标，不能在质量优越未成立后换口径宣布赢。
- **证明 B 值得加入：** 确认前固定 S−E 的检验路线为“质量优越”或“质量不劣且一个指定资源指标优越”；后者须预定不劣界限与资源指标/最小收益，不能用降低质量换省钱。否则正式产品采用 A，B 保持关闭。没有显著差异不等于两组相等，更不自动证明 B 无害。
- **证明人工管理可被部分替代：** S−H 先证明质量不劣，再证明主动管理时间下降；例如“不劣界限 5 个百分点、人时至少减少 15%”只是待负责人根据错误代价确认的候选标准，不是本次结果。失败/救援与总费用仍报告，不能仅凭少问人就称更有效。
- **多重比较：** 确认阶段事先指定主张顺序（S−D、S−E、S−H）并按固定顺序检验控制整体错误率；上游主张不成立，下游只作探索描述。若业务要独立回答多个主张，改用预先指定的多重比较调整并重算样本，不能两种方法事后择优。同一比较内也须提前指定唯一主资源指标及结论路线；若保留多个可独立获胜的指标/路线，必须一并调整多重性，不能事后从费用、时间、人时中挑胜项。
- **推广边界：** 报告覆盖的模型、版本、任务类型、项目、人员与预算。之后用至少 6 个全新目标 × D/S/H 的自然配置比较检验可用性和总体成本；这 18 个结果仍是迁移诊断，不替代正式样本。要声称优于其他 Agent，需增加当时真实可用且调校合理的对手，在等预算和自然配置两种条件下重测。

样本精度已作计算示例：15 个相互独立任务即使零次某类错误，其单侧 95% 错误率上界仍约 18.1%。假设 S 独赢 20%、D 独赢 10%，双侧精确配对检验 alpha=0.05，15/60/240 个独立目标的检出功效约为 2%/22%/79%。这只是指定假设下的二项分布计算，不是实际效果或批准的样本量；真实项目/人员聚类和多重比较可能需要更多样本。预算不足时诚实报告“探索性证据”，不制造超过人类的结论。

实验实施前需由负责人确定：允许使用的隔离项目/数据、付费调用和总人时额度、人工参与者、各任务 deadline/资源上限、独立验收者、质量不劣界限。它们是后续实验的执行条件；不阻塞本节设计交付，也不由已有测试推定同意。沿用既有实验/数据授权规则，不新增日常执行门禁。
