## Problem and scope
Static pi-compat inspection does not show that a candidate engine honors stop, usage, cancellation or settlement. The installed exact core/ai 0.86.1 tree can support offline qualification without paid provider calls. First implement isolated candidate staging and actual adapter subprocess qualification; then bind standalone root execution and resume to the qualified generation. No in-flight module replacement, native-host update, provider benchmark or production containment claim.

## Source-grounded constraints
PiAgentExecutor constructs the real Agent and waits for prompt/waitForIdle. Existing integration/pi-adapter/cost-stop.test.ts uses that real adapter with a deterministic faux provider and asserts one call after a priced tool turn. Reuse its behavior, not a substitute fake Agent.

Node resolves ESM imports relative to the importing module. cwd and NODE_PATH cannot redirect workspace imports. Installed pnpm junctions point into the workspace dependency tree; copying those links unchanged is not isolation. Stage physical packages and the actual built application with all transitive dependencies. A missing dependency beneath .agent_workspace can fall back to ancestor node_modules: resolve real paths and reject any module outside the candidate before evaluation. This is dependency isolation, not an OS filesystem/network sandbox.

The current CLI explicitly rebuilds executor configuration during resume. Managed binding must be additive durable Run/RUN_CREATED data, validated and replayed through existing stores, inherited by child/retry operations. An old run without binding retains its explicit legacy behavior. A managed run with missing original generation must refuse rather than use the newest one.

Existing writeFileAtomic Windows fallback temporarily moves the old file aside. Approved-selection readers and writers must share the existing manager lock; do not claim unlocked old-or-new visibility. Retain referenced generations and defer GC until actual reference-safe deletion is implemented.

## M5-D durable binding and controlled driver split
Source preflight separates D1 metadata validation/propagation from D2 actual whole-process loading. D1 adds optional Run.engineBinding with managed kind and opaque generation ID, validates through existing RUN_CREATED/CHILD_RUN_CREATED/EventStore/checkpoint paths, and propagates across coordinator parent/cluster children, supervisor rounds, flowchart start/resume replacement children and tracked clarification roots. Retry/cascade retain their existing executor. Resume compares authoritative run binding before dispatch; missing/mismatched generation refuses. Absence remains explicit legacy behavior. Do not store credentials, arbitrary executable paths or duplicate version registries in events; do not imply generation metadata proves which engine loaded or supplies actual model-version evidence for M7.

D2 selects one qualified retained generation before runtime imports and starts the staged application once. The child must verify its own physical staged identity and active import boundary before creating bound roots; a supplied binding string is not proof. Approving B affects new roots; existing A roots/children/retries/resumes remain A, and missing A cannot fall through to B/workspace. Preserve ordinary CLI/main export compatibility and distinguish persisted engine identity from legacy nonpersisted model/thinking configuration. No per-execute IPC executor or function serialization.

Current CLI has no process-signal cancellation wiring. A launcher must route one process-lifetime stop request into existing root cancel handles and flowchart/track abort scope, latch cancellation during startup, stop admission after disconnect, and wait actual adapter/child settlement. Killing or observing direct child close alone does not prove descendant settlement on Windows; forced/ambiguous termination retains unknown effects and cannot authorize automatic retry under another generation. Implement controlled offline staged-process tests and metadata propagation locally. Public real-project managed dispatch stays withheld under the existing M0 containment/Windows qualification condition; do not introduce a duplicate gate or unsafe bypass. Source mapping, exact propagation sites and existing event/CLI pinning tests: .agent_workspace/staged-continuation/m5-binding-preflight.md. This preflight executed no implementation or tests.
