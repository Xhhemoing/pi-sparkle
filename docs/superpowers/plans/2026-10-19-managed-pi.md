## Problem and scope
Static pi-compat inspection does not show that a candidate engine honors stop, usage, cancellation or settlement. The installed exact core/ai 0.86.1 tree can support offline qualification without paid provider calls. First implement isolated candidate staging and actual adapter subprocess qualification; then bind standalone root execution and resume to the qualified generation. No in-flight module replacement, native-host update, provider benchmark or production containment claim.

## Source-grounded constraints
PiAgentExecutor constructs the real Agent and waits for prompt/waitForIdle. Existing integration/pi-adapter/cost-stop.test.ts uses that real adapter with a deterministic faux provider and asserts one call after a priced tool turn. Reuse its behavior, not a substitute fake Agent.

Node resolves ESM imports relative to the importing module. cwd and NODE_PATH cannot redirect workspace imports. Installed pnpm junctions point into the workspace dependency tree; copying those links unchanged is not isolation. Stage physical packages and the actual built application with all transitive dependencies. A missing dependency beneath .agent_workspace can fall back to ancestor node_modules: resolve real paths and reject any module outside the candidate before evaluation. This is dependency isolation, not an OS filesystem/network sandbox.

The current CLI explicitly rebuilds executor configuration during resume. Managed binding must be additive durable Run/RUN_CREATED data, validated and replayed through existing stores, inherited by child/retry operations. An old run without binding retains its explicit legacy behavior. A managed run with missing original generation must refuse rather than use the newest one.

Existing writeFileAtomic Windows fallback temporarily moves the old file aside. Approved-selection readers and writers must share the existing manager lock; do not claim unlocked old-or-new visibility. Retain referenced generations and defer GC until actual reference-safe deletion is implemented.

The source-specific scratch design maps existing APIs and exact proposed commands: .agent_workspace/staged-continuation/m5-qualification-design.md; it performed no new tests.

Qualification issuance is process-local: a private WeakMap associates the exact frozen success object with a detached validated record bound to canonical manager/candidate roots, opaque generation and versions. Only the actual launcher/parent-validation path issues it. Store approval looks up that private record; copied/serialized objects, failures and another manager's receipt refuse. Restart reads manager-published local state, not a reconstituted issuance capability. Persisted JSON remains cooperative trusted-host state with strict ordinary validation; this is not authentication against malicious local editors or modified candidate code.

M5-C stores successful records outside immutable candidates at manager/qualifications/<UUID>.json, then publishes manager/approved.json under existing manager.lock. Every approved/qualified-generation reader takes the same lock and validates bounded regular files, candidate identity and required records; missing primary beside publication remnants is reconciliation-required. Never hold this lock during qualification. Failed B leaves approved A; pointer publication follows successful record publication, and ambiguity never falls through to latest/workspace. This is pointer-last cooperative publication, not a power-loss transaction or OS integrity proof. Retain all generations; no GC. Test actual parent issuance and clone refusal, failed runs/publications, corruption/remnants and a held Windows-style aside interval with a waiting locked reader. No extra hashes, signatures, baseline or gate are introduced.

M5-A path refinement from implementation inspection: reject a generations parent inside any tree that staging copies (program/dist or a discovered physical package root) before allocating the new generation. Otherwise copying can enumerate its own newly created destination and recurse. Ordinary path containment validation plus a bounded regression suffices; normal program/.agent_workspace remains allowed. This is input validation, not a new integrity or release gate.

## M5-C retained selection records and failure semantics (2026-10-20)
Implement one new managed/generation-store.ts and focused integration/pi-adapter/managed-generation-store.test.ts after M5-B review. ManagedGenerationStore(managerRoot, options) exposes approve(exactIssuedResult), readApproved() and getQualifiedGeneration(id). Only readApproved may return absent for a genuinely missing pointer with no publication remnants; a requested generation must exist and qualify or refuse. Capture ordinary options and the private issued record before awaiting the manager lock. Return detached frozen data, never an approval capability.

Reuse the existing file-lock and atomic writer. The only needed filesystem test seam forwards AtomicWriteOptions.rename, with mode0600 fixed; no worker/issuer/record-injection API. The manager root must already be a physical directory. All selection and qualification metadata reads use manager.lock, including corruption checks before approve; no nested public reader calls and no child execution under that lock. Keep bounded regular, single-linked descriptor reads local to the store; validate physical parents, size and file identity, and preserve the existing missing-primary/remnant ambiguity rule.

The qualification module supplies a data-only validateManagedQualificationRecord helper so persisted reads use the same strict scenario validation as issuance. It cannot populate the private WeakMap. Store compares canonical manager and derived generation roots, UUID, exact versions and completed candidate metadata under lock. This is cooperative host state, not hostile-writer integrity or renewed behavioral execution.

Existing qualifications/UUID.json is validated and reused, never overwritten on same-generation reapproval. It must match candidate identity/versions and contain valid observations; different successful attempts need not have byte-identical observations. An exact fresh issued result is still required for every approve call. No separate rollback API or JSON-to-capability conversion is added. This prevents an attempted reapproval from damaging a record already referenced by retained runs.

Qualification publication must precede approved.json. Failed qualification or qualification-record publication leaves the old pointer untouched. Failed pointer publication preserves the old selection when the existing atomic fallback restores it; if both publication and restoration fail, preserve remnants and make subsequent readers refuse for reconciliation. Do not promise that every I/O failure leaves readable old state. A successful but unselected qualification record is normal. Concurrent approvals serialize, last successful pointer wins, and no generations or qualification records are collected.

Actual tests must cover A then B with retained A, restart, exact receipt versus copies/JSON/wrong manager, repeated-record reuse without overwrite, corrupt current selection refusing new approval, missing candidate/record, symlinks/hardlinks/oversize, qualification-write failure, pointer-failure with successful rollback and failed rollback, and a paused Windows aside interval where a reader waits for manager.lock. Use finite release deadlines and finally cleanup to avoid a test deadlock. Detailed read-only source inventory is in .agent_workspace/staged-continuation/m5-selection-design.md; no store implementation or command verification follows from that inspection.
