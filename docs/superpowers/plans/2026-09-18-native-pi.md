## Problem and Scope

### Problem

Orchestration, tracking and learning are reached through a separate CLI instead of normal Pi sessions. The owner selected quality first, preferred `cursor-grok-4.6-fast`, and option B: project and global Pi configuration may be automatically changed; credentials and permission boundaries may not.

### In scope

Program: native session entry → shared orchestration → quality-first routing → context efficiency → independently verified automatic improvement. CLI remains supported. Preferred model resolves to `xhh/cursor-grok-4.6-fast` in the local model catalogue (configuration evidence, not provider availability or quality evidence). Keep the main conversation model stable; preference applies to delegated work unless explicitly changed by the user.

First slice: a packaged `sparkle_delegate` tool for 1–4 read-only scout/reviewer tasks; existing parent coordinator handles bounded concurrency, durable events, child tracking and cancellation. Reuse the host Pi registry/provider/auth without copying credentials. Stream compact progress and return bounded summaries + run identity. Invoke existing adaptation after terminal completion; it remains proposal-only. Session shutdown and tool abort cancel and settle active children. `SPARKLE_NATIVE=0` disables registration. No ambient conversation collection.

### Out of scope

First slice does not write project files, apply candidates, change global settings, auto-switch the main model, run commands in workers, or claim independent acceptance of model self-reports. Subsequent slices use isolated worktrees and independent checks before applying writes. Option B is standing scope authorization, not evidence that an unrestricted mutation mechanism exists. Global configuration candidates must use explicit non-credential/non-permission field allowlists, revision comparison, backups, verification, and rollback; package/tool activation and trust settings cannot be changed under that grant.

## Acceptance Criteria

- [x] Native package entry registers callable delegation and a status command; fails clearly for unavailable/ambiguous preferred models, never silently chooses a cheaper model.
- [x] Multiple delegated tasks execute via the existing coordinator with actual read tools, durable result refs and tracking; bounded summaries disclose that success is a child report, not independent verification.
- [x] Pre-abort starts no run; in-flight abort/shutdown settles children; no orphan provider work or post-cancel learning.
- [x] Credentials stay in the host auth path; no new auth/config writes or raw thinking data.
- [x] Entry loads using the installed Pi extension loader; focused tests, gate, adapter/security probes and documentation agree.
