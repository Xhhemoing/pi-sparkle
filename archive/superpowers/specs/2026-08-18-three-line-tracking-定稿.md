**关系：** 细化 ADR-004（执行 / 适应分离），不改写 M0–M2 的 run 真相。

请审阅人重点看：隔离是否够硬、分数会不会被游戏、路由会不会在数据不足时乱转向。文末有希望被挑战的问题。

---

## 1. 要解决什么

一次 live run 若能改自己的提示、路由或权限，就无法复现、也无法干净回滚。  
若第二条线每个回合都读完整对话和工具正文，费用会超过干活的模型。  
若只用平均「质量分」，一次口头 LGTM 或模型自评就能盖掉测试失败。

产品需要：**干活、盯过程、改未来策略** 三条线；便宜的滚轮跟踪；只有规则或用户说「有问题」才叫醒贵的分析；选模朝「过质量线且尽量便宜」走，且必须你批准才换下次规则。

---

## 2. 三条线

| 线 | 做什么 | 禁止做什么 |
| --- | --- | --- |
| **执行线** | 用已批准的契约、工具、路由完成任务 | 改活跃提示/路由/评分表/权限；把跟踪摘要当指令 |
| **跟踪线** | 记结构化事件，给本窗打分，把历史压成结构化摘要，只留给**自己下一轮** | 下令改策略；用自己的叙述证明任务已成功 |
| **分析线** | 只吃异常包，产出**版本化候选** | 补丁正在跑的 run；自动晋升；把思维链落盘 |

纠正「这一次的产出」：有界返工或停住问用户。  
改「以后怎么跑」：分析线 → 候选 → 用户明确晋升（CAS）。权限 / 安全 / 凭据永远不自动晋升。`adapt auto` 只许收集和提案。

---

## 3. 跟踪：本窗尽量细，历史用滚轮

每轮跟踪上下文 = 上一轮**结构化摘要** + 本轮高细节窗口 + 未关闭的小问题。

本轮高细节包括：新上下文、本轮用户/AI 文本、**工具调用情况**（名字、路径/范围、退出码、耗时、是否写入/越权、产物与证据 ID/哈希）。

**默认不读**工具正文、不读思维链。只有本轮已构成异常时才展开。

摘要是固定字段，不是散文：仍生效的约束、未决问题、已确认决策、操作清单、分数、异常码、证据引用、open-minors、**刻意省略了什么**。强制项（约束、权限、未决、失败的检查）不能被摘要掉；塞不下就记 omission 并失败关闭，不许装忘。

滚动摘要**只进跟踪线**，不进执行线。

---

## 4. 分数（分析线的门）

标尺一律 `[0,1]`。缺证据是 `UNOBSERVED`，禁止填 0.5。

**Prescore `P`（不含人类）** 看：证据是否一致、是否越权、该跑的检查有没有跑、早先约束还在不在、是否原地打转。叙述质量只能弃权，不能和测试平均。任一门相关维度失败，`P` 封顶 0.30。

优先级（不学权重）：确定性 > 用户显式对错 > 独立检查 > 跟踪可信度 > 执行自评（自评权重 0）。

**人类分 `H`（按顺序，先命中先用）**

1. 有可勾选清单：`H = 同意条数 / 可评价条数`
2. 用户写了 `x/10` 或「x分」：`H = x / 10`
3. 短句否定：整段打回 0.15；否这步但计划仍可 0.35；指出错误但继续 0.45

吃不准 → 当没评价。不要每轮逼打分，不要另请模型猜情绪。  
权限/安全上的不同意，不能被「5 条里同意了 4 条」冲掉。

**有明显人类问题**当且仅当：至少一条不同意，或打了分且 `< 8`，或短句否定命中。  
沉默、短确认（ok / 行 / 继续）、只补充需求但不指责当前操作 → 没有明显问题。

**综合分 `score`（是否进分析线）**

- 没评价，或没有明显问题 → `score = P`
- 否则 → `score = 0.7 × min(H, P) + 0.3 × max(H, P)`

软阈值：**绝对 `score < 0.55`**（与历史无关）。阈值版本化，由用户改，执行模型不能改。

**硬异常（不走 0.55）：** 测试/类型/lint 失败、写出任务所有权之外、声称已验证但没有任何检查事件、重复无进展、用户明确否定/叫停。

**小问题**（不碰安全/权限/失败检查、用户也没否）：先对事件/哈希/检查核实，禁止跟踪自己再「想一遍」。误报关掉；属实则记入 open-minors。可做不改计划、不改权限的廉价修补（例如重跑一次测试）。同一类连续 2 轮，或本 episode 累计 3 条未关闭，或碰到约束/用户反对，才升格进 `score`。

---

## 5. 分析线

输入：异常包（摘要、本轮结构化细节、`P/H/score`、哪道门、证据引用）。工具正文/思维链仅当本轮已异常。  
输出：一条边界清晰的版本化候选（提示 / 路由策略 / 评分表等只改一种），带证据和回滚目标。候选不等于已激活。  
模型：必要时比跟踪更强，尽量不与执行同一条；只吃异常包，不吃父 transcript。

---

## 6. 智能路由（最终算法）

这里的「权重」是 **某场景下在合格模型里偏好谁**，不是训练神经网络，也不是微调模型参数。本仓库 M7 之前不做权重训练。

### 6.1 一次任务怎么选

```text
定场景（taskFamily + role + 是否高风险）
  → R0 硬过滤（能力、隐私、高风险白名单）
  → 尚无用户批准的 routing-policy，或该格未过晋升门
        → 合格集合里最便宜（高风险只用白名单）
  → 已批准且该格 n_eff ≥ 5 且有独立来源（测试或人类）
        → LCB ≥ 质量线的最便宜者
        → 都过不了 → LCB 最高者（升级，不随机试探）
  → 执行
```

质量线：标准风险 0.55，高风险 0.70（高风险仍只在白名单内）。  
「适合」= **过线且尽量便宜**，不是选最强模型。

### 6.2 为什么不用 BKT / 三张独立表 / n=5 一刀切

- BKT 的猜测/失手/初始掌握会互相顶替（不可辨识）；模型也不会因为做对一题就「学会」。`P(T)=0` 的 BKT 不适合做可用性。BKT 若用，只留给以后的协作技能，不留给选模。
- 三张独立表会对不齐。必须是**一层可加收缩**。
- `n=5` 让估计器跳变。估计用连续收缩 `κ/(κ+n)`；`n=5` 只作为**晋升 live 排序**的治理门，不是「拒绝估计」。
- 在 0.55 切成对/错会丢掉三线中间信息。0.55 只叫醒分析线；路由用带信度的连续 `y`。
- 只按可用性排序会选更贵的模型。采用「过线最便宜，否则升级」。
- DKT / RouteLLM / NeuralUCB 不进 live（要训练集、难解释）。Checkpoint F 之后最多做离线对照，且必须在校准和成本上赢，不能只看 AUC。

### 6.3 一层收缩（闭式，无 MCMC）

先按现有 R1 半衰期做时间衰减，再向父层借力（Efron–Morris / Beta-Binomial 经验贝叶斯）：

```text
场景均值 μ_s     ← 该场景下所有模型/项目的 y
模型向场景收缩   p_m  = w_m  μ_s + (1-w_m)  ŷ_m     w = κ/(κ+n)
项目向场景收缩   p_p  同理
交互向「模型+项目」收缩   p_mp = w_mp p_add + (1-w_mp) ŷ_mp
p_add = clip(p_m + p_p − μ_s)
```

`κ` 用各格子成功率方差的矩估计，夹在 [2, 40]；格子少于 3 个时 `κ_s = 8`。交互默认 `κ_i = 16`（更狠，避免一次失败定终身）。

叶子用 Beta 近似算 **LCB**（均值 − 1.96×标准差）。样本少则 LCB 低，过不了质量线。

**归因（禁止再用平均分）：**

| 判断 | 条件 |
| --- | --- |
| 共性 / 场景本身难 | `μ_s` 的 LCB 低于质量线，且 ≥2 个模型、≥3 个项目有贡献 |
| 单个模型问题 | `p_m − μ_s` 的 LCB < −0.10，且交互项置信区间含 0 |
| 单个项目问题 | `p_p − μ_s` 的 LCB < −0.10，且交互项置信区间含 0 |
| 只在这里不行 | `p_mp − p_add` 的 LCB < −0.10 |
| 不确定 | 以上都不成立 → 不发 avoid/prefer |

共性或项目问题 → 加检查/改契约，**不**提案换更贵模型。模型或交互问题 → 才提案该类任务 avoid/prefer。效应阈值 0.10 与 0.55 一样版本化。

### 6.4 路由观察 `y`（和异常门分开）

| 情况 | y | 权重 |
| --- | --- | --- |
| 确定性失败或越权 | 0 | 1.0 |
| 确定性通过且无人类明显问题 | 1 | 1.0 |
| 有综合分且检查不是空的 | score | 0.6 |
| 有人类明显问题（走了 0.7/0.3 公式） | score | 0.8 |
| UNOBSERVED / 弃权 | 不更新后验 | 0（只记曝光） |

权重 < 1 就是「猜对/失手」该做的事：弱证据少推后验。沉默不是 0.5。

### 6.5 数据少 vs 数据够

- **估计器（适应平面一直开）：** 有曝光就算。n=0 用场景均值或保守 `Beta(1,1)`。无悬崖。
- **Live 排序（默认关）：** 必须用户批准 `routing-policy`，且目标格 `n_eff ≥ 5` 并有独立来源。
- 换模型版本或批准了提示/路由 → 重置该模型的格子；**保留**场景/项目难度（项目难不是模型的错）。
- 高风险探索次数永远为 0。Thompson 抽样只许影子。

### 6.6 怎么多攒标签、少花钱

1. 一分配就记曝光（合格集、拒绝原因、场景键、版本、影子倾向）。
2. 优先用「再跑一次测试」把空观察变成 0/1。
3. 空观察要留着，删掉会让模型看起来更好。
4. 缺标签格子只许影子回放，不许 live 试探。
5. 不要另请裁判模型给路由打标签。
6. Holdout 密封；更新只用 train/validation。
7. 落盘要同时留 `y` 和 weight，表才能回放。

### 6.7 路由如何一步步变合适（动态闭环）

```text
选模 → 干活 → 三线打分 → 更新收缩表
              → 影子对比「若按新表会选谁」（不驱动 live）
              → 有证据才生成一条 routing-policy 候选
              → 用户批准才改「下一趟」选法
              → 变差则 CAS 回滚上一指针
```

这是**离散、可回退的策略版本**，不是对话里偷偷漂权重。Checkpoint F 未关闭前，不得声称路由已是 Outcome-supported。

---

## 7. 隐私与落盘

持久化：结构化摘要、分数、omission、证据引用、曝光与 `y`。  
原始对话、工具正文：按 P0 仅引用或加密，**默认不进学习集**。  
思维链：仅异常时短暂读取，不落盘，不做回放依赖。  
分析线不接收执行者身份或其自我辩护。

## 8. 明确不做（本定稿范围外）

- 原始对话进学习集的细则、高风险探索、Outcome-supported 主张（规范默认 4–6 尚未逐条关）
- 把 BKT/DKT 接到 live 选模
- M3 工程缺口（episode 截断回放、覆盖率门接线等）
- Pi extension（ADR-006）
- 本仓库内 SFT/RL 训练

## 9. 希望审阅人挑战的问题

1. 软阈值 0.55、高风险质量线 0.70、归因效应 0.10 是否合理，还是应先用校准再定？  
2. 提案优先是否过严：表稳定后是否允许「仅 routing-policy、有独立证据、有回滚」的有限自动晋升？  
3. 概率可加 `p_m + p_p − μ_s` 是否应改成 logit 可加？  
4. 滚动摘要只进跟踪线，执行线会不会因缺少「刚才踩过的坑」而重复犯错？  
5. 路由 `y` 的 0.6/0.8 权重有没有更好的、仍可闭式计算的替代？

## 10. 决策一览

| 项 | 决定 |
| --- | --- |
| 三线 | 执行 / 跟踪 / 分析 |
| 滚轮摘要 | 只进跟踪线下一轮 |
| 本窗细节 | 上下文 + 工具情况；正文/思维链仅异常 |
| 综合分 | 无人类问题则 `P`；否则 `0.7min+0.3max` |
| 软阈值 | 绝对 0.55 |
| H | 占比 → 十分制 → 短句；吃不准当没评 |
| 十分制有问题 | 打了分且 < 8 |
| 小问题 | 核实 / 记帐 / 有界修补；2 轮或 3 条才升格 |
| 晋升 | 全部提案优先；adapt auto 只提案 |
| 路由估计 | 一层 Beta-Binomial 收缩 + LCB |
| Live 选模 | 默认 R0；批准后「过线最便宜，否则升级」 |
| 不用 | BKT/DKT 做 live 可用性；平均分诊断 |
